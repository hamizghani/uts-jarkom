W01.1 — Internet dan protokol

Mulai dari nol. Tidak ada prasyarat.

Apa itu Internet?

Internet adalah “network of networks”: banyak jaringan milik ISP (Internet Service Provider, penyedia layanan Internet) yang saling terhubung. Perangkat yang tersambung disebut host atau end system: laptop, HP, server, sampai kulkas.

Ada dua cara memandangnya:

  • Nuts and bolts: kumpulan perangkat keras (host, router, link) yang dijalankan oleh protokol.
  • Services: infrastruktur yang menyediakan layanan bagi aplikasi (Web, streaming, email, game). Internet juga memberi programming interface supaya aplikasi bisa memakainya.

Apa itu protokol?

Analogi manusia: kamu bilang “Hi”, dibalas “Hi”, lalu tanya “jam berapa?”, dijawab “2:00”. Ada urutan, ada format, dan ada tindakan setelah menerima pesan. Jaringan sama saja.

Definisi: protokol mendefinisikan format pesan, urutan pesan yang dikirim dan diterima, serta tindakan yang diambil saat pesan dikirim atau diterima.

Contoh urutan di jaringan: TCP connection request → TCP connection response → GET /file → isi file. Standar protokol Internet ditulis dalam RFC (Request for Comments) oleh IETF (Internet Engineering Task Force).

W01.2 — Network edge dan access network

Memakai istilah: host, ISP, protokol (bagian 1).

Tiga bagian Internet

Supaya tidak bingung, Internet dibagi tiga:

  1. Network edge: host (client dan server). Server banyak berada di data center.
  2. Access network dan physical media: link kabel atau nirkabel yang menyambungkan host ke router pertama.
  3. Network core: jaringan router yang saling terhubung (bagian 3).

Cara host mengirim data

Host memecah pesan aplikasi menjadi potongan kecil bernama packet, masing-masing L bit. Packet dikirim ke link dengan transmission rate R (bit per detik; disebut juga link capacity atau bandwidth). Waktu mendorong satu packet ke link:

d_trans = L / R

Contoh: L = 10 Kbit, R = 100 Mbps → 10.000 / 100.000.000 = 0,0001 detik = 0,1 msec.

  • Coaxial: dua konduktor konsentris, dua arah, banyak channel frekuensi.
  • Fiber optic: pulsa cahaya, satu pulsa = satu bit. Puluhan–ratusan Gbps, error rendah, kebal gangguan elektromagnetik.
  • Radio: tanpa kabel, broadcast, terpengaruh refleksi, halangan, dan interferensi. Satelit geostationary punya delay end-end sekitar 270 msec.

W01.3 — Network core

Memakai istilah: packet, L, R, d_trans (bagian 2).

Dua fungsi router

ForwardingRouting
CakupanLokal, di satu routerGlobal, seluruh jalur
TugasMemindahkan packet dari input link ke output link yang tepatMenentukan jalur sumber → tujuan (routing algorithm)

Cara kerjanya: router membaca destination address di header packet, mencarinya di forwarding table, lalu meneruskan ke output link hasil pencarian. Routing algorithm yang mengisi tabel itu. Contoh: header 0100 → link 3, 1001 → link 1.

Store-and-forward

Router harus menerima seluruh packet dulu sebelum mulai mengirimnya ke link berikutnya. Jadi bila packet melewati N link dengan rate sama (anggap tanpa antrian dan tanpa propagation delay):

delay end-to-end = N × L / R

Contoh: L/R = 0,1 msec dan 3 link → 0,3 msec.

Queueing dan loss

Jika laju packet yang datang ke suatu output link melebihi laju link itu mengirim, packet menunggu di buffer (antrian). Jika buffer penuh, packet dibuang (packet loss). Contoh: dua link masuk 100 Mb/s menuju satu link keluar 1,5 Mb/s, antrian pasti terbentuk.

Alternatif: circuit switching

Pada circuit switching, sumber daya sepanjang jalur dicadangkan khusus untuk satu “call” (seperti telepon tradisional). Terjamin, tetapi jatah itu idle bila tidak dipakai. Jatah dibagi dengan:

  • FDM: tiap call dapat pita frekuensi sendiri.
  • TDM: waktu dibagi slot; tiap call dapat slot periodik.

Packet switching vs circuit switching

Contoh: link 1 Gb/s. Tiap user memakai 100 Mb/s saat aktif, dan aktif hanya 10% waktu.

  • Circuit switching: 1 Gbps / 100 Mbps = 10 user.
  • Packet switching: 35 user tetap aman, sebab peluang lebih dari 10 user aktif bersamaan hanya sekitar 0,0004 (hitungan binomial n=35, p=0,1).

Packet switching cocok untuk data bursty (kadang kirim, kadang diam): resource dibagi, tanpa call setup. Kelemahannya: bisa terjadi kongesti, sehingga butuh protokol reliable data transfer dan congestion control (dibahas bab berikutnya).

Struktur Internet

Menyambungkan semua access ISP satu per satu butuh O(N²) koneksi, tidak scalable. Maka terbentuk bertahap: access ISP terhubung ke global transit ISP; karena ada banyak pesaing, mereka saling terhubung lewat IXP (Internet exchange point) atau peering link; muncul regional ISP; dan content provider network (Google, Microsoft, Akamai) membangun jaringan sendiri agar dekat dengan pengguna. Hasil akhirnya: tier-1 ISP di pusat, lalu regional ISP, lalu access ISP.

W01.4 — Performance: delay, loss, throughput

Memakai istilah: queueing, buffer, d_trans, store-and-forward (bagian 3).

Empat sumber delay

Satu packet yang melewati satu router mengalami empat delay berikut:

d_nodal = d_proc + d_queue + d_trans + d_prop

Visualisasi 4 Komponen Nodal Delay: d_trans (dorong bit ke kabel) vs d_prop (rambat gelombang di kabel).

  1. d_proc (processing): cek bit error dan tentukan output link. Biasanya < mikrodetik.
  2. d_queue (queueing): menunggu giliran di output link. Bergantung kongesti.
  3. d_trans = L/R: waktu mendorong seluruh bit packet ke link.
  4. d_prop = d/s: waktu satu bit merambat di kabel. d = panjang link, s ≈ 2×10⁸ m/s.

Jangan tertukar: d_trans bergantung pada ukuran packet dan rate; d_prop bergantung pada jarak dan media.

Contoh d_prop: link 2000 km → 2×10⁶ m / 2×10⁸ m/s = 0,01 detik = 10 msec, berapa pun ukuran packet-nya.

Analogi caravan (membedakan d_trans dan d_prop)

Mobil = bit, caravan = packet, booth tol = router. Booth butuh 12 detik per mobil, caravan 10 mobil, mobil melaju 100 km/jam, jarak antar booth 100 km.

  • Waktu “mendorong” seluruh caravan lewat booth (d_trans): 12 × 10 = 120 detik.
  • Waktu mobil terakhir menempuh 100 km (d_prop): 1 jam.
  • Total sampai caravan berbaris di booth kedua: 62 menit.

Jika mobil melaju 1000 km/jam dan booth butuh 1 menit per mobil, mobil pertama tiba di booth kedua pada menit ke-7 (1 menit dilayani + 6 menit jalan), saat 3 mobil masih di booth pertama. Artinya: bit pertama sebuah packet bisa tiba di router berikutnya sebelum bit terakhir selesai dikirim, bila d_prop lebih kecil daripada d_trans seluruh packet.

Traffic intensity

Misal a = rata-rata packet datang per detik, L = bit per packet, R = rate link. Maka:

traffic intensity = L·a / R

  • Dekat 0: queueing delay kecil.
  • Mendekati 1: queueing delay membesar tajam.
  • Lebih dari 1: kerja yang datang melebihi kemampuan layanan, delay rata-rata menuju tak hingga.

Packet loss

Buffer berkapasitas terbatas. Packet yang tiba saat buffer penuh dibuang. Packet yang hilang bisa dikirim ulang oleh node sebelumnya, oleh host sumber, atau tidak sama sekali.

Traceroute

Alat untuk mengukur delay dari sumber ke setiap router di jalur. Untuk router ke-i, traceroute mengirim 3 packet dengan TTL = i; router ke-i membalas, lalu waktu bolak-balik diukur. Tanda * * * berarti tidak ada balasan. Delay ke router jauh kadang tampak lebih kecil dari router sebelumnya karena tiap pengukuran terkena kondisi antrian yang berbeda.

Throughput

Throughput adalah laju bit yang sampai dari pengirim ke penerima (bit/detik). Bayangkan pipa air: server → link Rs → link Rc → client. Link paling sempit disebut bottleneck link.

throughput end-end = min(Rs, Rc); bila N koneksi berbagi backbone R: min(Rs, Rc, R/N)

Waktu transfer file F bit ≈ F / min(Rs, Rc).

W01.5 — Layering, encapsulation, dan security

Memakai istilah: packet, host, router, protokol (bagian 1–4).

Mengapa layering?

Jaringan terdiri dari banyak komponen. Layering membaginya jadi lapisan; tiap layer memberi satu service dengan memakai service layer di bawahnya. Manfaatnya: strukturnya eksplisit, dan mengganti implementasi satu layer tidak mengganggu layer lain (modular).

Lima layer Internet

LayerTugasContoh
applicationMendukung aplikasi jaringanHTTP, SMTP, IMAP, DNS
transportTransfer data proses ke prosesTCP, UDP
networkRouting datagram sumber → tujuanIP, routing protocol
linkTransfer data antar perangkat bertetanggaEthernet, WiFi 802.11
physicalBit di kabel—

Model OSI punya 7 layer: dua tambahan adalah presentation (enkripsi, kompresi, interpretasi data) dan session (sinkronisasi, checkpoint, recovery). Di Internet, bila dibutuhkan, keduanya dikerjakan aplikasi.

Encapsulation

Data dibungkus berlapis seperti boneka matryoshka. Tiap layer menambah header-nya sendiri:

  1. Application menghasilkan message M.
  2. Transport menambah header Ht → segment.
  3. Network menambah header Hn → datagram.
  4. Link menambah header Hl → frame.

Prinsip Enkapsulasi Matryoshka: Tiap layer menambahkan header identitas sebelum diteruskan ke layer bawah.

Di jalan, router hanya membuka sampai header network (Hn), sedangkan switch hanya sampai header link (Hl). Host tujuan membuka semua lapisan hingga application.

Security

Internet awalnya dirancang untuk pengguna yang saling percaya, jadi keamanan baru ditambal belakangan. Serangan umum:

  • Packet sniffing: pada media broadcast (WiFi, shared Ethernet), interface promiscuous merekam semua packet yang lewat. Wireshark adalah sniffer gratis.
  • IP spoofing: mengirim packet dengan alamat sumber palsu.
  • DoS (denial of service): membanjiri target agar tak bisa melayani trafik sah, sering memakai botnet (host yang sudah dibobol).

Pertahanan: authentication (mis. SIM card), enkripsi untuk confidentiality, digital signature untuk integrity, VPN, dan firewall (menyaring packet masuk, off-by-default).

Sejarah singkat

  • 1961–1972: prinsip packet switching; ARPAnet beroperasi 1969.
  • 1972–1980: internetworking (Cerf dan Kahn 1974), Ethernet 1976.
  • 1980–1990: TCP/IP 1983, DNS, SMTP, TCP congestion control 1988.
  • 1990-an: komersialisasi dan Web (HTML, HTTP oleh Berners-Lee).
  • 2005–kini: broadband, SDN (2008), cloud, mobile.

Prinsip Cerf dan Kahn: minimalism, autonomy, best-effort service, stateless routing, decentralized control.

Ringkasan W01

  • Internet = network of networks; protokol = format + urutan + aksi.
  • Edge (host), access (cable, DSL, WiFi, 4G/5G), core (router).
  • Packet switching (sharing, bursty) vs circuit switching (dedicated, FDM/TDM).
  • d_nodal = d_proc + d_queue + d_trans + d_prop; d_trans = L/R; d_prop = d/s.
  • Throughput = bottleneck; 5 layer; message → segment → datagram → frame.

W02.1 — Prinsip aplikasi jaringan

Konteks: aplikasi berjalan di network edge (host), bukan di network core.

Membuat aplikasi jaringan

Inti pembuatan aplikasi jaringan adalah menulis program yang berjalan pada end systems (host) yang berbeda dan saling berkomunikasi melalui jaringan (misalnya software web server berkomunikasi dengan browser). Perangkat di network core tidak menjalankan aplikasi pengguna. Hal ini membuat pengembangan dan penyebaran aplikasi berlangsung sangat cepat tanpa perlu izin atau konfigurasi di router inti.

Proses dan Socket

Program yang berjalan di dalam host disebut proses. Di dalam satu host, dua proses berkomunikasi lewat inter-process communication yang diatur oleh OS. Antara dua host yang berbeda, proses berkomunikasi dengan bertukar pesan (messages).

  • Client process: proses yang memulai komunikasi.
  • Server process: proses yang pasif menunggu untuk dihubungi.

Definisi Socket: socket adalah analogi "pintu" antara proses aplikasi dan protokol transport. Proses mendorong pesan keluar pintu socket, lalu mengandalkan infrastruktur transport layer di balik pintu untuk mengantar pesan ke socket tujuan. Bagian di atas socket dikendalikan oleh developer aplikasi; bagian di bawah socket dikendalikan oleh sistem operasi.

Pengalamatan proses (Addressing)

Agar pesan sampai ke proses yang tepat, alamat IP host saja tidak cukup karena satu host bisa menjalankan banyak proses aplikasi secara bersamaan. Identifikasi lengkap suatu proses membutuhkan:

Identifier Proses = Alamat IP (32-bit) + Port Number (16-bit)

Contoh port terkenal: HTTP Web server = port 80; Mail server (SMTP) = port 25.

W02.2 — Protokol transport untuk aplikasi: TCP vs UDP & TLS

Pilihan layanan protokol transport Internet yang tersedia untuk developer aplikasi.

Dua protokol transport Internet

FiturTCP (Transmission Control Protocol)UDP (User Datagram Protocol)
Model pengirimanReliable, in-order: data dijamin sampai dan sesuai urutan byte stream.Unreliable, unordered: pengiriman best-effort, paket bisa hilang atau terbalik urutannya.
ConnectionConnection-oriented: butuh handshake antara client dan server sebelum data dikirim.Connectionless: tanpa handshake, langsung kirim independen.
Flow & Congestion ControlAda flow control (tidak membanjiri receiver) dan congestion control (menahan laju saat jaringan macet).Tidak ada. UDP mengirim data secepat yang diinginkan aplikasi.
Jaminan yang tidak adaTidak ada jaminan delay (timing) dan tidak ada jaminan bandwidth minimum.Tidak ada jaminan delay dan bandwidth minimum.

Mengapa ada UDP?

Jika TCP andal, mengapa UDP dibutuhkan? UDP unggul karena tanpa delay setup koneksi (menghemat RTT), sederhana tanpa memelihara state di server/client, ukuran header kecil (hanya 8 byte), dan tanpa batas congestion control sehingga sangat cocok untuk DNS, streaming audio/video langsung, SNMP, dan protokol modern seperti HTTP/3 (QUIC).

Mengamankan TCP: TLS

TCP dan UDP vanilla tidak memiliki enkripsi bawaan; password dan data dikirim dalam bentuk cleartext. TLS (Transport Layer Security) berjalan di application layer di atas TCP. Aplikasi memakai library TLS yang mengenkripsi data sebelum dikirimkan ke socket TCP, sehingga menyediakan enkripsi, data integrity, dan autentikasi endpoint.

W02.3 — Web dan HTTP: koneksi & waktu respon

Hypertext Transfer Protocol (HTTP) adalah protokol utama Web yang berjalan di atas TCP port 80 (atau HTTPS port 443).

HTTP Overview & Sifat Stateless

Halaman Web tersusun dari objek-objek (file HTML dasar, gambar JPEG, CSS, script) yang dialamatkan oleh URL (contoh: http://site.com/dept/pic.gif terdiri dari host name site.com dan path name /dept/pic.gif).

HTTP bersifat Stateless: server tidak menyimpan informasi apapun tentang request client sebelumnya. Desain stateless menjaga protokol tetap sederhana dan tahan terhadap crash, karena tidak perlu rekonsiliasi state yang rusak antar pihak.

Non-persistent vs Persistent HTTP

FiturNon-persistent HTTP (HTTP/1.0)Persistent HTTP (HTTP/1.1)
MekanismeKoneksi TCP dibuka, paling banyak 1 objek dikirim, koneksi langsung ditutup.Koneksi TCP tetap dibiarkan terbuka setelah respons dikirim. Banyak objek dikirim lewat 1 koneksi.
OverheadButuh koneksi TCP baru untuk tiap objek referensi (overhead CPU dan memori di server/OS).Hanya 1 koneksi TCP untuk seluruh halaman beserta objek-objek referensinya.
Waktu responButuh 2 RTT per objek.Dapat mengambil semua objek referensi hanya dalam ~1 RTT (dengan pipelining).

Hitungan Response Time dan RTT

RTT (Round-Trip Time) adalah waktu yang dibutuhkan paket kecil untuk bepergian dari client ke server lalu kembali ke client.

Response Time Non-persistent per objek:

Response Time = 2 × RTT + file transmission time

1 RTT untuk TCP handshake + 1 RTT untuk HTTP request/response pertama + waktu transmisi file.

Contoh kasus: Sebuah halaman HTML dasar mereferensikan 10 gambar JPEG.

  • Non-persistent serial: 1 RTT handshake + 1 RTT base HTML + 10 × (1 RTT handshake + 1 RTT gambar) = 22 RTT (plus waktu transmisi).
  • Persistent dengan pipelining: 1 RTT handshake + 1 RTT base HTML + 1 RTT untuk mengambil seluruh 10 gambar sekaligus = 3 RTT. Respon time terpangkas drastis!

Perbandingan Waktu Respon HTTP: Non-persistent (2 RTT per objek) vs Persistent Pipelining (~3 RTT total).

W02.4 — Format pesan HTTP, cookies, dan web caching

Pesan HTTP berbasis teks ASCII yang terbaca oleh manusia.

Format Pesan HTTP

Pesan HTTP terbagi dua: Request dan Response.

Contoh HTTP Request:

GET /index.html HTTP/1.1\r\n
Host: www-net.cs.umass.edu\r\n
User-Agent: Mozilla/5.0 Firefox/80.0\r\n
Connection: keep-alive\r\n
\r\n
  • Baris 1 = Request line: Method + spasi + URL + spasi + Version + \r\n.
  • Baris berikutnya = Header lines: nama field dan nilainya.
  • Baris kosong (\r\n) menandai akhir header, diikuti Entity body opsional (pada POST/PUT).

Metode HTTP Request

  • GET: mengambil objek dari server. Input form dapat diselipkan di URL setelah tanda tanya (query parameter).
  • POST: mengirimkan input pengguna di dalam entity body request (misal form login atau submit data).
  • HEAD: meminta hanya baris status dan header saja, tanpa body objek (berguna untuk testing/caching).
  • PUT: mengunggah file baru ke URL yang ditentukan, menggantikan objek yang ada secara penuh.

Kode StatusArtiPenjelasan

301 Moved PermanentlyRedirectObjek telah dipindahkan ke URL baru yang dicantumkan pada header Location:.
400 Bad RequestClient ErrorPesan request tidak dipahami oleh server karena kesalahan format/sintaks.

Cookies: Menjaga State Pengguna

Karena HTTP bersifat stateless, situs web menggunakan cookies untuk mengenali pengguna dan mempertahankan sesi (seperti shopping cart atau login session).

Empat komponen sistem cookie:

  1. Header Set-Cookie: ID_unik pada HTTP response dari server.
  2. Header Cookie: ID_unik pada HTTP request berikutnya dari client ke server.
  3. File cookie yang disimpan di perangkat client dan dikelola browser.
  4. Database back-end di server yang memetakan ID cookie ke profil/riwayat pengguna.

Alur Kerja Sistem Cookie: Mempertahankan sesi dan state pengguna di atas protokol HTTP yang stateless.

First-party vs Third-party Cookie: First-party disetel oleh domain yang dikunjungi langsung. Third-party cookie disetel oleh domain pihak ketiga (misalnya jaringan iklan AdX yang tertanam di halaman) untuk melacak perilaku browsing pengguna lintas berbagai situs web tanpa disadari pengguna. Berdasarkan regulasi GDPR, cookie yang dapat mengidentifikasi individu dikategorikan sebagai data pribadi yang wajib mendapatkan izin eksplisit pengguna.

Web Caching (Proxy Server)

Web cache bertindak sebagai server bagi client dan sebagai client bagi origin server. Tujuannya memenuhi permintaan client tanpa harus selalu menghubungi origin server.

Contoh efisiensi Web Cache:

Access link institusi 1,54 Mbps, RTT Internet ke server = 2 detik. Laju request 15/detik, ukuran objek 100 Kbit (total kebutuhan 1,50 Mbps).

  • Tanpa cache: utilisasi link $= 1{,}50 / 1{,}54 = 0{,}97$ (97%). Delay antrian membengkak hingga hitungan menit!
  • Upgrade link ke 154 Mbps: utilisasi turun ke 0,0097, namun biaya sewa link sangat mahal dan RTT Internet 2 detik tetap ada.
  • Pasang Web Cache lokal (hit rate 0,4): 40% request dipenuhi lokal dalam hitungan milidetik. Trafik di access link terpangkas $40\%$ sehingga utilisasi turun ke 0,58 (antrian hilang). Rata-rata delay: $0{,}6 \times 2\text{ s} + 0{,}4 \times (\sim 0) \approx 1{,}2\text{ detik}$. Jauh lebih murah dan lebih cepat!

Conditional GET

Browser cache memastikan salinan lokal tetap segar tanpa membuang bandwidth. Client mengirimkan header If-modified-since: <date>. Jika objek belum berubah sejak tanggal tersebut, server membalas dengan:

HTTP/1.0 304 Not Modified (tanpa mengirimkan data body lagi, sangat menghemat data).

W02.5 — Evolusi HTTP: HTTP/2 dan pengantar HTTP/3

Mengatasi kendala latensi dan performa transfer multi-objek.

Head-of-Line (HOL) Blocking pada HTTP/1.1

HTTP/1.1 mendukung pipelined GET, namun server harus merespons secara berurutan sesuai urutan request (First-Come First-Served). Jika objek pertama berukuran raksasa atau butuh waktu proses lama di database, semua objek kecil di belakangnya akan tertahan (Head-of-Line Blocking).

HTTP/2 (RFC 7540, 2015)

HTTP/2 mempertahankan metode, status code, dan semantik HTTP/1.1, tetapi mengubah cara transfer data:

  • Binary Framing Layer: data tidak lagi dikirim sebagai teks biasa, melainkan dibagi menjadi frame biner dalam stream bernomor.
  • Frame Interleaving: frame dari objek-objek kecil disisipkan di antara frame objek besar, sehingga objek kecil selesai diunduh dengan cepat tanpa menunggu objek besar tuntas.
  • Prioritisasi: client dapat menentukan prioritas resource yang lebih penting (mis. CSS sebelum gambar).
  • Server Push: server dapat proaktif mengirimkan resource tambahan yang belum diminta client tetapi pasti dibutuhkan.
  • HPACK: kompresi header untuk mengurangi ukuran request/response.

Keterbatasan HTTP/2 dan Lahirnya HTTP/3 (QUIC)

HTTP/2 menyatukan semua stream ke dalam satu koneksi TCP. Masalahnya: jika ada satu paket TCP yang hilang di jaringan, garansi in-order delivery milik TCP akan menahan seluruh stream sampai paket yang hilang berhasil diretransmisi (TCP-level HOL blocking).

HTTP/3: memindahkan transport dari TCP ke QUIC yang berjalan di atas UDP. Tiap stream memiliki penanganan loss independen, mengintegrasikan enkripsi TLS 1.3, dan memangkas waktu setup koneksi menjadi 1-RTT atau bahkan 0-RTT.

W02.6 — DNS (Domain Name System)

Layanan direktori pemetaan nama host ke alamat IP dan sebaliknya.

Mengapa DNS?

Manusia mudah mengingat nama host (seperti cs.ui.ac.id), sedangkan router jaringan membutuhkan alamat IP 32-bit (seperti 152.118.24.10). DNS adalah database terdistribusi yang diimplementasikan dalam hierarki server nama dan merupakan protokol application-layer yang berjalan di atas UDP port 53.

Fungsi DNS

  • Translasi Hostname ke IP address.
  • Host aliasing: nama kanonikal (asli) memiliki satu atau lebih nama alias yang lebih ramah pengguna.
  • Mail server aliasing: mengarahkan email domain ke mail server resmi.
  • Load distribution: satu nama host memetakan ke sekumpulan alamat IP server yang direplikasi; DNS mengacak urutan IP pada setiap balasan (round-robin).

Mengapa DNS Tidak Disentralisasi?

DNS tidak bisa dipusatkan pada satu mega-server karena: rentan single point of failure, volume trafik raksasa (ratusan miliar hingga triliunan query/hari), jarak geografis menyebabkan delay tinggi, dan perawatan database yang tidak mungkin di-maintain satu entitas.

Hierarki Tiga Tingkat DNS

  1. Root DNS Servers: titik kontak terakhir bagi server yang tidak bisa me-resolve nama. Terdapat 13 alamat root server logis di seluruh dunia (dikelola ICANN dan direplikasi ratusan kali secara fisik).
  2. Top-Level Domain (TLD) Servers: bertanggung jawab atas domain tingkat atas seperti .com, .org, .edu, dan kode negara seperti .id, .uk.
  3. Authoritative DNS Servers: server milik organisasi/institusi yang menyimpan catatan nama-ke-IP resmi untuk server milik mereka sendiri.
  4. Local DNS Server: server lokal milik ISP atau kampus. Saat host mengirim query DNS, pesan pertama kali diarahkan ke local DNS server-nya (bertindak sebagai proxy dan cache).

Setelah name server mempelajari mapping suatu nama, mapping tersebut disimpan di dalam cache lokal. Jika ada query berikutnya untuk nama yang sama, server langsung membalas dari cache tanpa perlu menelusuri hierarki. Entri cache kedaluwarsa setelah jangka waktu TTL (Time-To-Live).

Keamanan DNS

  • DDoS: upaya membanjiri Root atau TLD server dengan trafik palsu. Root server terlindungi oleh filter paket dan caching TLD pada local DNS server.
  • DNS Spoofing / Cache Poisoning: penyerang mencegat query DNS dan membalas dengan IP palsu untuk mengalihkan korban ke situs berbahaya.

Ringkasan W02

  • Aplikasi berjalan di end system (edge), memakai arsitektur client-server atau P2P. Proses diidentifikasi oleh IP + Port melalui interface socket.
  • TCP menyediakan koneksi andal, in-order, flow control, dan congestion control; UDP menyediakan transmisi cepat best-effort tanpa delay setup. TLS mengamankan TCP di application layer.
  • HTTP bersifat stateless di port 80. Non-persistent butuh 2 RTT/objek; Persistent (HTTP/1.1) butuh ~1 RTT untuk semua objek referensi.
  • Cookies mempertahankan state di atas protokol stateless. Web cache menghemat bandwidth link dan memangkas response time secara signifikan; Conditional GET memakai status 304 Not Modified.
  • HTTP/2 menyelesaikan HOL blocking di level aplikasi memakai binary framing dan frame interleaving; HTTP/3 (QUIC) memindahkan transport ke UDP untuk membasmi TCP-level HOL blocking dan menyediakan 0-RTT.
  • DNS adalah database terdistribusi hierarkis (Root, TLD, Authoritative) dengan record A, NS, CNAME, MX. Resolusi iterated menjaga beban server root tetap ringan.

W03.1 — Multimedia video dan streaming stored video

Konteks: streaming video mengonsumsi ~80% bandwidth Internet residensial global (Netflix, YouTube, Amazon Prime).

Karakteristik Video dan Video Coding

Video adalah urutan gambar digital yang ditampilkan pada laju konstan (misalnya 24 atau 30 frame per detik). Kompresi (coding) video memanfaatkan redundansi bit:

  • Spatial redundancy (dalam satu gambar): alih-alih mengirimkan $N$ nilai piksel berwarna sama (misal ungu), pengirim cukup mengirimkan nilai warna ungu dan angka pengulangan $N$.
  • Temporal redundancy (antar gambar berurutan): alih-alih mengirim seluruh frame $i+1$, pengirim hanya mengirimkan selisih perbedaan (delta) dibandingkan frame $i$.

CBR vs VBR:

  • CBR (Constant Bit Rate): laju bit kompresi video dijaga tetap konstan sepanjang video.
  • VBR (Variable Bit Rate): laju bit kompresi berubah-ubah secara dinamis mengikuti kompleksitas gambar (misal adegan aksi cepat membutuhkan bitrate lebih tinggi dibanding gambar statis).

Contoh format: MPEG-1 (CD-ROM, 1,5 Mbps); MPEG-2 (DVD, 3–6 Mbps); MPEG-4 (standar Internet, 64 Kbps–12 Mbps).

Tantangan Streaming Stored Video

Pada skenario streaming, client mulai memutar bagian awal video saat server masih mengirim bagian akhir. Tantangan utamanya:

  1. Variasi bandwidth: kapasitas link server-ke-client terus berubah akibat fluktuasi kongesti di jaringan akses dan network core.
  2. Jitter dan Packet Loss: keterlambatan dan kehilangan paket dapat merusak pengalaman menonton.
  3. Continuous Playout Constraint: waktu pemutaran frame di client harus persis sama dengan waktu pemutaran aslinya, tidak boleh tersendat (freeze/buffering).

Playout Buffering di Sisi Client

Untuk menyerap variasi delay (jitter) dari jaringan, client menerapkan client-side buffering:

Cara kerja: Saat streaming dimulai, client menunda pemutaran selama beberapa detik (initial playout delay) sambil mengisi buffer lokal. Ketika pemutaran dimulai, frame dibaca dari buffer dengan laju konstan. Fluktuasi kedatangan paket jaringan diserap oleh buffer sehingga pemutaran tetap mulus.

W03.2 — DASH (Dynamic, Adaptive Streaming over HTTP)

Standar streaming adaptif modern yang mendominasi layanan video online.

Arsitektur DASH

DASH memisahkan video menjadi potongan-potongan kecil dan menyerahkan keputusan pemilihan bitrate kepada client.

  • Server: memotong file video menjadi banyak chunk (biasanya berdurasi 2 hingga 10 detik per chunk). Tiap chunk di-encode pada beberapa level bitrate/kualitas berbeda (misal 360p, 720p, 1080p, 4K). Server menyediakan file katalog bernama Manifest File (MPD) yang memuat URL untuk tiap chunk dan varian kualitasnya.
  • Client: secara periodik mengukur bandwidth yang tersedia antara server dan client. Berdasarkan pembacaan manifest, client meminta chunk satu per satu dengan memilih rate encoding tertinggi yang sanggup dipertahankan tanpa membuat buffer kosong (starvation).

"Kecerdasan" berada di sisi Client:

  1. Kapan meminta chunk (menghindari buffer starvation dan buffer overflow).
  2. Encoding rate apa yang diminta (memilih kualitas setinggi mungkin saat jaringan lancar, dan menurunkan resolusi saat jaringan lambat).
  3. Dari mana meminta chunk (memilih URL server CDN yang paling dekat atau memiliki bandwidth tertinggi).

Formula streaming modern: Streaming Video = Encoding + DASH + Playout Buffering.

Arsitektur DASH: Server menyediakan video multi-rate; Client secara cerdas memilih resolusi chunk sesuai fluktuasi bandwidth.

W03.4 — Transport layer: prinsip dan layanan

Lapisan yang menyediakan komunikasi logis antar proses aplikasi di host yang berbeda.

Transport Layer vs Network Layer (Analogi Rumah Tangga)

Bayangkan 12 anak di rumah Ann (East Coast) berkirim surat ke 12 anak di rumah Bill (West Coast):

  • Hosts: Rumah Ann dan Rumah Bill.
  • Processes: Anak-anak di masing-masing rumah.
  • Application Messages: Surat yang dimasukkan ke dalam amplop.
  • Transport Layer Protocol: Ann dan Bill yang bertugas mengumpulkan surat dari saudara mereka (multiplexing) dan membagikan surat yang datang ke anak yang tepat (demultiplexing).
  • Network Layer Protocol: Layanan Pos (kantor pos dan kurir) yang mengantar tumpukan surat antar rumah.

Prinsip inti: Network layer bertanggung jawab atas komunikasi host-ke-host; Transport layer bertanggung jawab atas komunikasi proses-ke-proses.

Aksi Protokol Transport Layer

  • Sisi Pengirim (Sender): menerima pesan dari application layer, memecahnya menjadi potongan data, menambahkan header transport ($H_t$) untuk membuat segment, lalu meneruskannya ke network layer (IP).
  • Sisi Penerima (Receiver): menerima segment dari IP, memeriksa kebenaran header, mengekstrak pesan aplikasi, dan melakukan demultiplexing ke socket proses yang sesuai.

W03.5 — Multiplexing dan demultiplexing

Dasar pengiriman data ke proses yang tepat menggunakan nomor port.

Konsep Multiplexing & Demultiplexing

  • Multiplexing (di pengirim): mengumpulkan potongan data dari berbagai socket aplikasi, menyisipkan header transport (termasuk nomor port), lalu mengemasnya menjadi segmen.
  • Demultiplexing (di penerima): membaca informasi header pada segmen transport yang diterima untuk mengarahkan segmen ke socket aplikasi yang tepat.

Format Segmen dan Nomor Port

Header transport (baik TCP maupun UDP) memiliki lebar minimum 32 bit per baris dengan dua field identitas utama:

Source Port # (16 bit) | Destination Port # (16 bit)

Port bernilai antara 0 hingga 65535: port 0–1023 adalah well-known ports (misal HTTP 80, HTTPS 443, DNS 53); port 1024–49151 adalah registered ports; port 49152–65535 adalah dynamic/ephemeral ports yang diberikan OS untuk client.

Connectionless Demultiplexing (UDP)

Pada socket UDP (dibuat dengan new DatagramSocket(port)):

  • Host pengirim secara eksplisit menyertakan Destination IP dan Destination Port pada datagram.
  • Host penerima hanya memeriksa Destination Port untuk mengarahkan segmen ke socket yang sesuai.
  • Poin penting ujian: Datagram UDP yang datang dari Source IP atau Source Port yang berbeda, selama memiliki Destination Port yang sama, akan diarahkan ke socket UDP yang sama di host penerima. Field Source Port berguna sebagai alamat balasan bagi penerima.

Connection-Oriented Demultiplexing (TCP)

Pada socket TCP:

  • Socket TCP diidentifikasi oleh 4-tuple lengkap:

4-tuple TCP = (Source IP, Source Port, Destination IP, Destination Port)

  • Host penerima menggunakan keempat nilai ini sekaligus untuk mengarahkan segmen ke socket yang tepat.
  • Contoh: Sebuah web server dengan IP B mendengarkan koneksi di port 80. Client 1 (IP A, port 9157) dan Client 2 (IP C, port 9157) sama-sama mengirim ke B:80. Karena Source IP keduanya berbeda (A vs C), segmen di-demultiplex ke dua socket TCP yang berbeda di server B, meskipun port tujuannya sama-sama 80.

Perbandingan Demultiplexing: UDP hanya memeriksa Port Tujuan; TCP memeriksa 4-tuple lengkap.

W03.6 — Protokol UDP dan Internet checksum

User Datagram Protocol (RFC 768): protokol transport minimalis tanpa handshaking.

Karakteristik UDP

  • "No frills", "bare bones": ekstensi paling tipis di atas layanan best-effort IP.
  • Connectionless: tidak ada handshaking; setiap segmen diproses independen dari segmen lain.
  • Segmen dapat hilang atau tiba di luar urutan (out-of-order).
  • Tanpa congestion control: UDP mentransmisikan data secepat yang diinginkan aplikasi tanpa menahan diri.
  • Penggunaan: streaming video/audio (toleran loss, sensitif rate), query DNS, manajemen SNMP, dan HTTP/3 (keandalan ditangani di application layer).

Struktur Header UDP (8 Byte)

Field Header (16 bit tiap field)Fungsi

Cara Kerja Internet Checksum

Internet Checksum bertujuan mendeteksi perubahan bit (bit flip) yang terjadi pada segmen selama melewati kabel dan router.

Prosedur di Pengirim (Sender):

  1. Isi segmen UDP (header, data, dan IP pseudo-header) diperlakukan sebagai barisan bilangan bulat 16-bit.
  2. Semua bilangan dijumlahkan secara one's complement. Jika terjadi carry-out pada bit paling signifikan (MSB), carry tersebut harus ditambahkan kembali ke bit paling belakang (wraparound).
  3. Hasil penjumlahan dibalik setiap bitnya (operasi bitwise NOT / one's complement), lalu diletakkan di field checksum.

Prosedur di Penerima (Receiver):

Penerima menjumlahkan seluruh bilangan 16-bit termasuk nilai checksum yang diterima dengan aturan wraparound yang sama. Jika tidak ada bit yang rusak, hasil penjumlahan harus menghasilkan seluruh bit bernilai 1 (0xFFFF). Jika ada satu bit saja bernilai 0, error terdeteksi!

Contoh Hitungan Checksum (Penjumlahan Dua Bilangan 16-bit)

  1110011001100110  (0xE666)
+ 1101010101010101  (0xD555)
------------------
1 1011101110111011  (17 bit: ada carry-out 1 di MSB)

Lakukan wraparound (tambahkan carry 1 ke hasil):

  1011101110111100  = Sum (0xBBBC)

Balik semua bit (1's complement) untuk mendapatkan Checksum:

  0100010001000011  = Checksum (0x4443)

Kelemahan Internet Checksum

Internet Checksum memberikan proteksi error yang lemah. Jika terjadi beberapa bit flip yang saling meniadakan (misalnya pada bilangan pertama bit berubah dari 10 menjadi 01 [-1], dan pada bilangan kedua bit berubah dari 01 menjadi 10 [+1]), nilai total penjumlahan dan checksum tidak akan berubah! Kerusakan bit tersebut akan lolos tanpa terdeteksi oleh UDP.

  • CDN memecahkan keterbatasan mega-server melalui pendekatan Enter Deep (dekat user) atau Bring Home (di POP). Integrasi DNS via CNAME mengarahkan pengguna ke server CDN terbaik.
  • Transport layer menyediakan komunikasi logis antar proses (beda dengan network layer yang host-ke-host).
  • Demultiplexing UDP hanya mengandalkan Destination Port. Demultiplexing TCP mengandalkan 4-tuple lengkap: (src IP, src port, dest IP, dest port).
  • UDP adalah protokol connectionless, best-effort, dengan header ramping 8 byte. Checksum dihitung dari 1's complement sum 16-bit dengan wraparound, namun memiliki kelemahan terhadap error yang saling meniadakan.

W04.1 — Prinsip transport layer dan demultiplexing lanjutan

Memakai istilah: host, port, IP datagram, segment (W01–W03).

Kedudukan Transport Layer

Transport layer menyediakan logical communication antar proses aplikasi yang berjalan di host berbeda. Protokol transport hanya berjalan di end system (host), bukan di router perantara. Router di network core hanya memproses sampai Network Layer (IP).

  • Sender: memecah pesan aplikasi menjadi segment, menyematkan transport header ($T_h$), lalu meneruskan ke layer IP.
  • Receiver: menerima segmen dari IP, memverifikasi header, mengekstrak pesan aplikasi, lalu melakukan demultiplexing ke socket yang tepat.

Welcoming Socket vs Connection Socket pada Server TCP

Pada server TCP (misal web server di port 80), terdapat pemisahan socket penting:

  • Welcoming Socket: socket utama yang dibuat saat server mulai berjalan dan menjalankan listen() pada port terkenal (misal port 80). Fungsinya pasif menyambut kontak awal (TCP handshake) dari client baru.
  • Connection Socket: saat koneksi client diterima lewat pemanggilan accept(), sistem operasi membuat sebuah socket koneksi baru khusus untuk berkomunikasi dengan client tersebut.

Jika ada $N$ client yang terhubung bersamaan ke web server, maka terdapat $N + 1$ socket aktif di server, semuanya tetap berbagi local port 80 yang sama tetapi dibedakan oleh 4-tuple unik masing-masing.

W04.2 — Socket programming: UDP dan TCP (Python)

Socket API menyediakan interface pemrograman aplikasi jaringan antara user space dan kernel OS.

Socket sebagai "Pintu"

Socket adalah pintu penghubung antara proses aplikasi dan transport protocol. Segala kode di atas socket dikendalikan oleh developer aplikasi; segala protokol di bawah socket dikendalikan oleh sistem operasi.

Socket UDP di Python: SOCK_DGRAM

UDP tidak memiliki koneksi (connectionless). Data dikirim per datagram dengan melampirkan alamat tujuan secara eksplisit pada setiap pengiriman.

UDP Client:

from socket import *
serverName = 'hostname'
serverPort = 12000
clientSocket = socket(AF_INET, SOCK_DGRAM)
message = input('Input lowercase sentence: ')
clientSocket.sendto(message.encode(), (serverName, serverPort))
modifiedMessage, serverAddress = clientSocket.recvfrom(2048)
print(modifiedMessage.decode())
clientSocket.close()

UDP Server:

from socket import *
serverPort = 12000
serverSocket = socket(AF_INET, SOCK_DGRAM)
serverSocket.bind(('', serverPort))
print("The server is ready to receive")
while True:
    message, clientAddress = serverSocket.recvfrom(2048)
    modifiedMessage = message.decode().upper()
    serverSocket.sendto(modifiedMessage.encode(), clientAddress)

Socket TCP di Python: SOCK_STREAM

TCP bersifat connection-oriented. Client harus melakukan connect() yang memicu 3-way handshake sebelum data dapat dialirkan.

TCP Client:

from socket import *
serverName = 'servername'
serverPort = 12000
clientSocket = socket(AF_INET, SOCK_STREAM)
clientSocket.connect((serverName, serverPort))
sentence = input('Input lowercase sentence: ')
clientSocket.send(sentence.encode())
modifiedSentence = clientSocket.recv(1024)
print('From Server:', modifiedSentence.decode())
clientSocket.close()

TCP Server:

from socket import *
serverPort = 12000
serverSocket = socket(AF_INET, SOCK_STREAM)
serverSocket.bind(('', serverPort))
serverSocket.listen(1)
print('The server is ready to receive')
while True:
    connectionSocket, addr = serverSocket.accept()
    sentence = connectionSocket.recv(1024).decode()
    capitalizedSentence = sentence.upper()
    connectionSocket.send(capitalizedSentence.encode())
    connectionSocket.close()

Siklus Hidup Koneksi TCP: Pembukaan koneksi (3-Way Handshake) dan penutupan dua arah (4-Step Teardown dengan TIME_WAIT).

Perbedaan Karakteristik Byte Stream vs Datagram

  • UDP (Message Boundary): satu panggilan sendto() menghasilkan satu datagram mandiri, dan dibaca utuh oleh satu panggilan recvfrom(). Batas pesan terjaga.
  • TCP (Byte Stream): tidak ada batas pesan ("pipe" byte berkelanjutan). Satu panggilan recv(1024) bisa membaca potongan dari satu send() atau gabungan dari beberapa send(). Aplikasi harus membingkai pesannya sendiri (misal dengan separator newline atau field panjang).

W04.3 — Struktur segmen TCP dan sequence/ACK number

TCP (RFC 793, 1122, 2018, 5681, 7323) menyediakan transmisi byte-stream andal point-to-point.

Fitur Utama TCP

  • Point-to-point: satu pengirim dan satu penerima (tidak mendukung broadcast/multicast).
  • Reliable, in-order byte stream: data tiba utuh dan berurutan.
  • Full duplex data: data dua arah dapat mengalir bersamaan dalam satu koneksi.
  • Cumulative ACKs: acknowledgment menyatakan nomor byte berikutnya yang diharapkan.
  • Pipelining: window size memungkinkan pengiriman banyak segmen sekaligus (data in-flight).
  • Flow controlled & Congestion controlled.

  1. Host A → Host B: Seq=42, ACK=79, data='C' (A mengirim byte 42; A mengharapkan byte 79 dari B).
  2. Host B → Host A: Seq=79, ACK=43, data='C' (B meng-ACK byte 42 dengan mengirim ACK=43; B mengirimkan balasan echo 'C' dengan Seq=79 miliknya sendiri). Teknik ini disebut piggybacking (menumpangkan ACK pada segmen data).
  3. Host A → Host B: Seq=43, ACK=80 (A meng-ACK byte 79 dari B dengan mengirim ACK=80; tidak ada data yang dikirim).

W04.4 — TCP RTT dan Timeout Interval

Bagaimana menentukan durasi timer timeout retransmisi TCP secara dinamis?

Dilema Nilai Timeout

  • Jika timeout terlalu pendek: terjadi premature timeout, memicu retransmisi sia-sia untuk paket yang sebenarnya tidak hilang.
  • Jika timeout terlalu panjang: reaksi terhadap packet loss sangat lambat, menurunkan throughput.
  • Karena RTT jaringan terus berubah, timeout harus diestimasi secara adaptif.

Estimasi RTT (EstimatedRTT)

SampleRTT adalah waktu yang diukur dari pengiriman segmen hingga ACK diterima (mengabaikan retransmisi — Karn's Rule). Untuk menghaluskan fluktuasi, TCP memakai EWMA (Exponential Weighted Moving Average):

EstimatedRTT = (1 - α) × EstimatedRTT + α × SampleRTT

Nilai rekomendasi standar: α = 0,125 (1/8). Pengaruh sampel lama menyusut secara eksponensial.

Variasi RTT (DevRTT) dan Rumus Timeout

DevRTT mengukur seberapa jauh SampleRTT menyimpang dari EstimatedRTT (jitter):

DevRTT = (1 - β) × DevRTT + β × |SampleRTT - EstimatedRTT|

Nilai rekomendasi standar: β = 0,25 (1/4).

Rumus Akhir Timeout Interval:

TimeoutInterval = EstimatedRTT + 4 × DevRTT

Suku 4 × DevRTT bertindak sebagai safety margin. Jika jaringan stabil, margin kecil; jika jitter tinggi, margin membesar agar tidak premature timeout.

Contoh Hitungan RTT

Diketahui nilai awal: EstimatedRTT = 100 ms, DevRTT = 10 ms, dan pengukuran baru SampleRTT = 140 ms. Gunakan $\alpha = 0{,}125$ dan $\beta = 0{,}25$:

  1. DevRTT = (1 - 0,25) × 10 + 0,25 × |140 - 100| = 7,5 + 10 = 17,5 ms.
  2. EstimatedRTT = (1 - 0,125) × 100 + 0,125 × 140 = 87,5 + 17,5 = 105 ms.
  3. TimeoutInterval = 105 + 4 × 17,5 = 175 ms.

Exponential Backoff: jika timer timeout kedaluwarsa sebelum ACK tiba, TCP menggandakan nilai TimeoutInterval (2×) sebagai mitigasi kongesti darurat, hingga data baru berhasil di-ACK.

W04.6 — Fast retransmit, flow control, dan congestion control

Optimalisasi kinerja dan kontrol transmisi data TCP.

TCP Fast Retransmit

Menunggu timer timeout bisa memakan waktu terlalu lama. Ketika sebuah segmen hilang, penerima akan mengirimkan duplicate ACK setiap kali menerima segmen berikutnya yang berada di atas celah (gap).

Mekanisme Fast Retransmit:

Jika pengirim menerima 3 duplicate ACKs untuk data yang sama (total 4 ACK identik: 1 ACK asli + 3 duplicate), pengirim segera meretransmisi segmen dengan seq number terkecil yang belum di-ACK tanpa menunggu timer timeout habis!

Contoh: Segmen 200 hilang. Kedatangan segmen 300, 400, dan 500 masing-masing memicu ACK=200 (3 duplicate). Segmen 200 langsung dikirim ulang.

Mekanisme TCP Fast Retransmit: Penerimaan 3 duplicate ACKs memicu retransmisi instan tanpa menunggu timer timeout habis.

Flow Control

Flow control adalah mekanisme proteksi untuk mencegah pengirim membanjiri buffer penerima (receiver buffer overflow).

  • Penerima mengalokasikan buffer penerima (RcvBuffer).
  • Penerima secara dinamis mengiklankan ruang buffer yang masih kosong melalui field receive window (rwnd) pada setiap segmen ACK yang dikirim ke pengirim:

rwnd = RcvBuffer - [LastByteRcvd - LastByteRead]

  • Pengirim menjamin bahwa jumlah data yang belum di-ACK (in-flight) tidak akan melebihi rwnd: LastByteSent - LastByteAcked ≤ rwnd. Jika rwnd = 0, pengirim tetap mengirim segmen probe 1-byte secara berkala agar mengetahui kapan buffer penerima kembali kosong.

Congestion Control (Ringkasan)

Flow control melindungi penerima; Congestion control melindungi jaringan dari kemacetan router. Pengirim membatasi laju data berdasarkan congestion window (cwnd):

Window Efektif = min(cwnd, rwnd)

  • Slow Start: cwnd dimulai dari 1 MSS dan berlipat ganda (2×) setiap RTT hingga mencapai ambang batas (ssthresh).
  • Congestion Avoidance: setelah ssthresh tercapai, cwnd naik linier sebesar 1 MSS per RTT (Additive Increase).
  • Reaksi terhadap loss: jika terdeteksi 3 duplicate ACK, cwnd dipotong setengah (Multiplicative Decrease / AIMD); jika terjadi timeout, cwnd jatuh kembali ke 1 MSS dan memulai Slow Start lagi.

Ringkasan W04

  • Transport layer beroperasi di end systems. Server TCP memiliki 1 welcoming socket (listen) dan $N$ connection socket (accept) yang dibedakan oleh 4-tuple.
  • Socket programming Python: UDP memakai SOCK_DGRAM (message boundary, sendto/recvfrom); TCP memakai SOCK_STREAM (byte stream, connect, listen, accept, send/recv).
  • Header TCP minimal 20 byte. Sequence number menghitung byte data pertama; ACK number bersifat kumulatif (next expected byte). MTU 1500 B → MSS 1460 B.
  • TimeoutInterval dihitung dari $EstimatedRTT + 4 \times DevRTT$ menggunakan EWMA ($\alpha=0{,}125, \beta=0{,}25$). Karn's rule melarang pengukuran RTT pada retransmisi.
  • Receiver menghasilkan Delayed ACK (500 ms) atau Duplicate ACK jika ada gap. Cumulative ACK menyelamatkan kehilangan ACK sebelumnya.
  • Fast Retransmit dipicu oleh 3 duplicate ACKs (triple duplicate ACK). Flow control diatur oleh rwnd; Congestion control diatur oleh cwnd.

W05.1 — Latar belakang dan Head-of-Line (HOL) blocking

Konteks: hubungan Application Layer di user space dan Transport Layer di kernel OS.

Hubungan Application Layer dan Transport Layer

  • Application Layer: berisi protokol yang berinteraksi langsung dengan pengguna (HTTP, FTP, SMTP). HTTP hanya membutuhkan transfer data yang andal tanpa perlu memikirkan detail routing atau retransmisi.
  • Transport Layer: menyediakan komunikasi end-to-end (TCP atau UDP). TCP menyediakan keandalan, flow control, dan congestion control di kernel OS.
  • Web standar berjalan di TCP port 80 (HTTP) atau port 443 dengan TLS (HTTPS).
  • Pada QUIC / HTTP/3, tumpukan protokol diubah secara radikal: HTTP berjalan di atas UDP + QUIC menggantikan TCP.

Tiga Jenis Head-of-Line (HOL) Blocking (Jangan Tertukar!)

Istilah Head-of-Line Blocking merujuk pada fenomena antrian di mana elemen terdepan yang terhambat menahan semua elemen di belakangnya. Di materi jaringan terdapat tiga jenis HOL blocking:

W05.2 — HTTP/2: binary framing dan multiplexing

HTTP/2 (RFC 7540, 2015) bertujuan memangkas delay pada pengambilan halaman web dengan banyak objek.

Fitur Utama HTTP/2

  • Metode (GET, POST), status code (200, 404), dan semantik header tidak berubah dari HTTP/1.1.
  • Binary Framing Layer: pesan HTTP dipecah menjadi frame-frame biner terstruktur (HEADERS frame, DATA frame) yang dikelompokkan ke dalam stream bernomor.
  • Interleaving (Multiplexing): pengiriman frame diselang-seling dalam satu koneksi TCP tunggal.
  • Prioritisasi Resource: client dapat menentukan prioritas objek (misalnya file CSS dan JS tata letak halaman didahulukan sebelum file video atau gambar besar).
  • Server Push: server dapat proaktif mengirimkan resource yang belum diminta client tetapi pasti dibutuhkan untuk merender halaman.
  • HPACK: kompresi header menggunakan tabel statis, tabel dinamis, dan Huffman coding untuk memangkas duplikasi header antar request.

Ilustrasi Interleaving Menghilangkan HTTP HOL Blocking

Skenario: Client meminta 1 objek besar O1 (80 frame) dan 3 objek kecil O2, O3, O4 (masing-masing 2 frame). Kecepatan transmisi 1 frame/ms:

  • HTTP/1.1 (FCFS serial): O1 selesai pada 80 ms, O2 selesai pada 82 ms, O3 pada 84 ms, O4 pada 86 ms. Objek kecil menderita karena tertahan di belakang O1. Rata-rata selesai: 83 ms.
  • HTTP/2 (Interleaved round-robin): Frame dikirim selang-seling (O1, O2, O3, O4, O1, O2, O3, O4, lalu sisa O1). Objek kecil O2 selesai pada 6 ms, O3 pada 7 ms, O4 pada 8 ms, dan O1 selesai pada 86 ms. Rata-rata waktu selesai terpangkas drastis menjadi 26,75 ms! Browser bisa mulai merender halaman seketika.

Kelemahan Fatal HTTP/2 di Atas TCP

Karena HTTP/2 memadatkan banyak stream ke dalam satu koneksi TCP tunggal, garansi in-order delivery TCP di kernel menjadi bumerang:

Jika terjadi packet loss pada satu frame (misal milik stream video), TCP layer di client akan menahan semua frame berikutnya di kernel dan tidak mengalirkannya ke aplikasi sampai frame yang hilang berhasil diretransmisi. Akibatnya, semua stream objek lain (gambar, CSS) ikut macet total.

Evolusi Mengatasi Head-of-Line Blocking: Dari HTTP/1.1 (App HOL) ke HTTP/2 (TCP HOL) hingga HTTP/3 (QUIC Independent Streams).

W05.3 — Solusi QUIC dan arsitektur HTTP/3

Mengapa QUIC dibangun di atas UDP di user space, bukan dengan merevisi TCP?

Mengapa Tidak Memperbarui TCP di Kernel?

  1. TCP diimplementasikan di dalam OS kernel. Memperbarui TCP mengharuskan miliaran perangkat dan server di dunia meng-update OS mereka, yang memakan waktu bertahun-tahun.
  2. Ossification of the Internet: perangkat perantara jaringan (firewall, NAT, middlebox) hanya mengenali protokol TCP dan UDP standar. Jika dibuat protokol transport baru pengganti TCP di layer 4, paket akan dibuang oleh firewall.

Solusi Praktis: QUIC di Atas UDP

Solusi yang diambil adalah menggunakan UDP sebagai pembawa (carrier), lalu membangun protokol transport modern bernama QUIC (Quick UDP Internet Connections) di application layer (user space). Karena berjalan di user space, QUIC dapat di-update dengan cepat cukup dengan meng-update aplikasi browser atau web server.

Fitur-Fitur Kunci QUIC

  • Keamanan Bawaan (TLS 1.3 Mandatory): QUIC mengintegrasikan TLS 1.3 langsung ke dalam transport handshake. Tidak ada opsi plaintext, tidak ada downgrade ke TLS 1.2 atau 1.1.
  • Multi-stream tanpa TCP HOL Blocking: tiap stream memiliki mekanisme reliable data transfer (RDT) dan enkripsi tersendiri. Jika terjadi packet loss pada stream A, hanya stream A yang tertahan; stream B dan C tetap mengalir lancar.
  • Shared Congestion Control: semua stream dalam satu koneksi QUIC berbagi satu pengendali kongesti bersama, menjaga keadilan alokasi bandwidth jaringan seperti satu koneksi TCP.
  • Unique Packet Number (Mencegah Ambiguitas Retransmisi): setiap paket QUIC memiliki nomor urut yang selalu bertambah unik, bahkan ketika mengirim ulang data yang hilang. Hal ini menghilangkan ambiguitas ACK pada kalkulasi RTT (mengatasi kendala Karn's rule pada TCP).
  • Connection ID (CID) & Connection Migration: koneksi TCP diikat oleh 4-tuple IP dan port sehingga jika IP berubah, koneksi putus (reset). QUIC mengidentifikasi koneksi menggunakan Connection ID (CID) 64-bit yang independen dari alamat IP. Ketika smartphone berpindah dari WiFi rumah ke jaringan seluler 4G/5G, koneksi QUIC tetap berjalan mulus (seamless migration) tanpa perlu mengulang handshake.

    • QUIC Connection Migration: Connection ID 64-bit membebaskan sesi dari ikatan alamat IP/port fisik.

Mekanisme 0-RTT Connection Establishment

  1. Pada koneksi QUIC pertama kali, server mengirimkan TLS session ticket terenkripsi yang kemudian disimpan di cache client.
  2. Saat client ingin menghubungi server yang sama di kemudian hari, client menyertakan session ticket tersebut langsung pada paket pertama yang dikirim ke server.
  3. Data aplikasi (misalnya HTTP GET request) dapat langsung ditumpangkan pada paket pertama tersebut: 0-RTT handshake delay! Data langsung terkirim tanpa menunggu balasan handshake terlebih dahulu.

Catatan Keamanan 0-RTT: Paket pada 0-RTT rentan terhadap serangan replay attack karena server belum bisa memverifikasi kesegaran waktu paket. Oleh karena itu, 0-RTT hanya diizinkan untuk request idempoten yang aman (seperti HTTP GET), dan dilarang untuk transaksi pembayaran/POST.

Evaluasi Performa QUIC (Dissecting Production QUIC, WWW '21)

  • Objek Kecil: HTTP/3 secara konsisten mengungguli HTTP/2 sebesar 10%–50% karena penghematan handshake 0-RTT dan 1-RTT mendominasi total waktu muat objek kecil.
  • Kondisi Jaringan Buruk (Extra Loss & Extra Delay): keunggulan QUIC melonjak tajam karena stream independen kebal terhadap efek domino packet loss yang melumpuhkan HTTP/2.
  • Objek Besar: performa QUIC bervariasi bergantung pada optimasi algoritma congestion control dan implementasi stack di masing-masing vendor.

W05.6 — Persiapan webserver untuk QUIC dan HTTP/3

Langkah-langkah praktis mengonfigurasi infrastruktur server untuk mengadopsi HTTP/3.

Langkah Penerapan di Sisi Server

  1. Update Web Server Software: gunakan software yang mendukung QUIC dan HTTP/3, seperti Caddy (dukungan native), Nginx-QUIC, LiteSpeed, atau cloud edge seperti Cloudflare dan Google Cloud CDN. Server harus mendukung TCP dan UDP sekaligus.
  2. Dukungan Wajib TLS 1.3: pasang sertifikat SSL/TLS valid (misal via Let's Encrypt). QUIC menolak koneksi tanpa TLS 1.3.
  3. Buka Port UDP 443: banyak firewall dan security group cloud secara default hanya membuka TCP 443. Port UDP 443 wajib dibuka dan ukuran buffer UDP disesuaikan agar tidak terjadi packet drop saat trafik tinggi.
  4. Kirim Header Alt-Svc: webserver mengirimkan response header Alt-Svc: h3=":443"; ma=86400 saat client berkunjung via HTTP/2, memberitahukan bahwa layanan HTTP/3 tersedia di port UDP 443.
  5. Integrasi CDN & Fallback TCP: CDN secara otomatis menangani terminasi QUIC di edge. Jika jaringan pengguna memblokir trafik UDP, client secara otomatis mundur (fallback) ke HTTP/2 di atas TCP.
  6. Monitoring dan Testing: verifikasi melalui tab Network browser DevTools (kolom Protocol menampilkan h3), perintah CLI curl --http3 https://domain, atau alat online seperti http3check.net.

Ringkasan W05

  • HTTP/1.1 mengalami HOL blocking di level aplikasi akibat antrian respons FCFS pipelining.
  • HTTP/2 menyelesaikan HOL aplikasi dengan binary framing dan frame interleaving, namun memicu TCP-level HOL blocking karena semua stream berbagi satu koneksi byte-stream TCP.
  • QUIC dibangun di atas UDP di user space untuk mengatasi keterbatasan kernel dan ossification middlebox.
  • QUIC mengintegrasikan TLS 1.3, independent streams, common congestion control, unique packet numbering, dan Connection Migration berbasis Connection ID (CID).
  • QUIC memangkas handshake menjadi 1-RTT untuk koneksi awal dan 0-RTT untuk koneksi berulang via session ticket.
  • Media over QUIC (MoQ) menggabungkan latensi ultra-rendah RTP dengan skalabilitas fan-out CDN. Penerapan webserver membutuhkan TLS 1.3, pembukaan port UDP 443, dan header Alt-Svc.

W06.2 — Arsitektur di dalam router dan queueing

Bagaimana komponen internal router memproses jutaan paket per detik.

Komponen Utama Router

  1. Input Ports: menerima sinyal fisik kabel (line termination), memproses frame link layer (Ethernet receive), melakukan lookup forwarding table, dan menampung antrian input.
  2. Switching Fabric: jaringan bus internal kecepatan tinggi yang menghubungkan input port ke output port.
  3. Output Ports: menampung antrian paket keluar (buffer), menjalankan link layer send, dan mentransmisikan bit ke link fisik.
  4. Routing Processor (Control Plane): CPU yang menjalankan protokol routing (software), memelihara tabel routing, dan mengunduh forwarding table ke input ports.

Arsitektur Internal Router: Pemisahan Control Plane (Routing Processor) dan Data Plane (Input Port, Fabric, Output Port).

Decentralized Switching di Input Port

Agar router mampu bekerja pada line speed (kecepatan penuh kabel tanpa jeda), setiap input port menyimpan salinan lokal forwarding table di memorinya sendiri. Saat paket tiba, port langsung mencocokkan header tujuan ("match plus action") dan meneruskannya ke switching fabric tanpa perlu bertanya ke routing processor CPU utama.

Di Mana Antrian (Queueing) Terbentuk?

  • Input Queueing: terjadi jika switching fabric lebih lambat daripada laju gabungan input ports. Antrian di input port memicu Head-of-the-Line (HOL) Blocking: paket di depan antrian yang menunggu output port sibuk akan menghalangi paket di belakangnya yang ingin menuju output port bebas.
  • Output Queueing: terjadi saat paket tiba dari switching fabric lebih cepat daripada laju transmisi link keluar ($R$). Paket menumpuk di buffer output port. Jika buffer penuh, terjadi packet loss (antrian meluap).

Berapa Ukuran Buffer Router yang Ideal?

Aturan Praktis Tradisional (RFC 3439):

Buffer = RTT × C

Contoh: RTT tipikal 250 ms pada link $C = 10\text{ Gbps} \rightarrow 0{,}25\text{ s} \times 10\text{ Gbps} = \mathbf{2{,}5\text{ Gbit}}$ buffer.

Rekomendasi Modern dengan N Flows:

Buffer = (RTT × C) / √N

Jika ada $N = 10.000$ flow TCP bersamaan: $2{,}5\text{ Gbit} / \sqrt{10.000} = 2{,}5\text{ Gbit} / 100 = \mathbf{25\text{ Mbit}}$ (100× lebih kecil!). Karena fluktuasi ribuan flow tidak tersinkronisasi, buffer kecil sudah cukup menjaga link tetap penuh tanpa memicu bufferbloat (delay antrian raksasa pada router rumah).

Buffer Management: Drop & Marking

  • Tail Drop: jika buffer penuh, paket yang baru tiba langsung dibuang. Sederhana, namun dapat memicu TCP global synchronization (semua pengirim melambat bersamaan).
  • Priority Drop: membuang paket berkategori prioritas rendah terlebih dahulu saat buffer penuh.
  • RED (Random Early Detection): router mulai membuang atau menandai paket secara acak sebelum buffer benar-benar penuh, sehingga pengirim TCP mengurangi laju secara bertahap dan bergantian.
  • ECN (Explicit Congestion Notification): router tidak membuang paket, melainkan mencentang bit ECN pada header IP. Penerima mengabarkan pengirim via bit ECE di header TCP sehingga pengirim melambat tanpa kehilangan data.

Rumus Jatah Bandwidth WFQ:

Jatah Kelas i = (w_i / Σ w_j) × R

Contoh: Link $R = 6\text{ Mbps}$. Bobot kelas 1: $w_1 = 1$, kelas 2: $w_2 = 2$, kelas 3: $w_3 = 3$ (total bobot = 6). Jika salah satu kelas kosong, sisa kapasitas dibagi proporsional ke kelas yang aktif.

Isu Network Neutrality: prinsip bahwa semua penyedia Internet (ISP) wajib memperlakukan seluruh paket secara setara tanpa diskriminasi atau manipulasi prioritas berdasarkan sumber, tujuan, atau jenis aplikasi.

IPv6: Format dan Keunggulan

IPv6 diciptakan karena ruang 32-bit IPv4 (~4,3 miliar alamat) telah habis teralokasi. IPv6 memiliki ruang alamat 128-bit ($3{,}4 \times 10^{38}$ alamat).

  • Header Berukuran Tetap 40 Byte: menyederhanakan dan mempercepat pemrosesan hardware di router.
  • Field header IPv6: Version (4), Traffic Class (8, prioritas flow), Flow Label (20), Payload Length (16), Next Header (8, menunjukkan protokol layer transport atau extension header), Hop Limit (8, pengganti TTL), Source Address (128 bit), Destination Address (128 bit).
  • Yang Dihilangkan dari IPv4:
    • Tidak ada Checksum: link layer dan transport layer sudah memiliki error check; menghilangkan checksum menghemat CPU router karena tidak perlu menghitung ulang tiap hop.
    • Tidak ada Fragmentasi di Router: router tidak memecah paket; jika paket terlalu besar, router membalas pesan ICMP "Packet Too Big". Fragmentasi hanya boleh diinisiasi host pengirim.
    • Tidak ada Options di header utama: dipindahkan ke extension headers via field next header.

Transisi dari IPv4 ke IPv6: Tunneling

Seluruh router di dunia tidak mungkin di-upgrade secara serentak (tidak ada "flag day"). Transisi dilakukan dengan strategi Dual-Stack dan Tunneling:

Mekanisme Tunneling:

Saat datagram IPv6 harus melintasi jaringan router IPv4 di tengah jalur, router perbatasan dual-stack membungkus seluruh datagram IPv6 sebagai payload di dalam datagram IPv4 baru (IPv4 header memuat src = Router_B, dest = Router_E, protocol field = 41). Router IPv4 di tengah hanya melihat header IPv4 luar. Di ujung terowongan (Router E), header IPv4 dilepas (decapsulation), dan datagram IPv6 asli diteruskan ke tujuan.

W06.6 — Subnetting: FLSM dan VLSM

Teknik pembagian ruang alamat IP secara efisien.

Apa itu Subnet?

Definisi Subnet: kumpulan antarmuka (interface) perangkat yang dapat saling berkomunikasi secara fisik tanpa perantara router. Cara mencarinya: putuskan setiap sambungan ke router; setiap "pulau" jaringan yang terisolasi adalah sebuah subnet.

Subnet Mask dan Proses ANDing

Subnet mask memisahkan bagian network dan bagian host:

Network Address = IP Address AND Subnet Mask

Contoh: Host 192.168.10.77 dengan mask 255.255.255.192 (/26):
Oktet 4 IP: 77 = 01001101
Oktet 4 Mask: 192 = 11000000
01001101 AND 11000000 = 01000000 (64) → Network Address = 192.168.10.64/26.
Host bits = 6 → Block size = 64. Broadcast = 192.168.10.127. Usable host = .65 s.d. .126.

FLSM (Fixed Length Subnet Mask / Static Subnetting)

Pada FLSM, seluruh subnet memiliki ukuran mask yang sama:

  • Meminjam $b$ bit dari host part menghasilkan $2^b$ subnet.
  • Sisa bit host $h$ menghasilkan $2^h - 2$ alamat host usable per subnet.
  • Kelemahan fatal FLSM: sangat boros alamat. Jika jaringan membutuhkan subnet untuk 28 host dan link point-to-point untuk 2 host, seluruh subnet harus disamakan ukurannya mengikuti kebutuhan terbesar (/27 dengan 30 host). Link 2 host membuang 28 alamat IP sia-sia!

VLSM (Variable Length Subnet Mask)

VLSM membagi ruang alamat secara hierarkis dengan subnet mask yang ukurannya disesuaikan secara dinamis mengikuti kebutuhan riil masing-masing jaringan.

Langkah Prosedur VLSM yang Benar:

  1. Hitung prefix minimum yang mencukupi kebutuhan usable host masing-masing jaringan ($2^h - 2 \ge \text{kebutuhan}$).
  2. Wajib: Urutkan alokasi dari kebutuhan host terbesar ke terkecil! (Mengalokasikan blok besar terlebih dahulu mencegah fragmentasi alamat).
  3. Pastikan alamat awal setiap subnet selalu jatuh pada kelipatan dari block size-nya.
  4. Alokasikan berurutan; sisa ruang alamat di bagian belakang tetap utuh sebagai satu blok kontigu besar.

Ringkasan W06

  • Network layer terbagi atas Data Plane (forwarding lokal nanodetik) dan Control Plane (routing global milidetik). Layanan Internet mengusung prinsip Best Effort.
  • Router terdiri dari input ports, output ports, switching fabric, dan routing processor. Input port melakukan decentralized lookup berbasis line speed. Antrian output membutuhkan buffer $(RTT \times C)/\sqrt{N}$.

W07.1 — IPv6 lanjutan dan aturan penyingkatan

Format penulisan dan kompresi alamat 128-bit sesuai standar RFC 5952.

Struktur Alamat IPv6

Alamat IPv6 berukuran 128 bit, dibagi menjadi 8 grup (hextet) masing-masing 16 bit, ditulis dalam notasi heksadesimal dan dipisahkan oleh tanda titik dua (:).

Bentuk Penuh: 2001:0db8:0000:0000:0000:ff00:0042:8329

Aturan Penyingkatan (RFC 5952)

  1. Hilangkan Leading Zeros: angka nol di depan dalam setiap hextet harus dihilangkan (misal 0db8 → db8, 0042 → 42, 0000 → 0).
  2. Rangkaian Nol Berurutan Terpanjang Diganti ::: blok 0:0:0 dapat disingkat menjadi tanda titik dua ganda (::). Tanda :: hanya boleh muncul satu kali saja dalam satu alamat agar tidak ambigu!
  3. Pecah Seri (Tie-Break): jika ada beberapa rangkaian nol berurutan dengan panjang yang sama, gunakan :: pada rangkaian yang paling kiri.
  4. Jangan Singkat Nol Tunggal: jika hanya ada satu hextet bernilai 0, tetap tulis :0: (jangan gunakan :: untuk satu nol tunggal).
  5. Huruf Heksadesimal Wajib Lowercase: tulis a sampai f dalam huruf kecil.

W07.2 — DHCP (Dynamic Host Configuration Protocol)

Dua Pertanyaan Pengalamatan Jaringan

  1. Bagaimana host memperoleh alamat IP di dalam subnet-nya? → Dijawab oleh DHCP.

  • Mendukung pengguna mobile yang sering berpindah jaringan.

W07.3 — Alokasi IP, route aggregation, dan ICANN

Bagaimana blok alamat didistribusikan dari badan dunia ke ISP dan pelanggan.

Hierarchical Addressing dan Route Aggregation

ISP memperoleh blok alamat besar dari registri regional, lalu membaginya menjadi subnet-subnet yang lebih kecil untuk para pelanggannya.

Contoh Pembagian Blok ISP:

ISP memiliki blok 200.23.16.0/20 (mencakup rentang 200.23.16.0 s.d. 200.23.31.255). ISP membaginya menjadi 8 blok pelanggan masing-masing berukuran /23:

  • Organisasi 0: 200.23.16.0/23
  • Organisasi 1: 200.23.18.0/23
  • Organisasi 2: 200.23.20.0/23
  • ... s.d. Organisasi 7: 200.23.30.0/23

Route Aggregation: Alih-alih mengiklankan 8 rute individual ke seluruh router Internet, ISP cukup mengiklankan satu rute ringkas tunggal: 200.23.16.0/20 ("Kirimkan semua paket berawalan 200.23.16.0/20 ke saya"). Hal ini membuat tabel routing global tetap kecil dan efisien.

More Specific Routes

Bagaimana jika Organisasi 1 (200.23.18.0/23) berganti ISP ke "ISPs-R-Us", tetapi ingin mempertahankan alamat IP lamanya? ISP baru akan mengiklankan rute spesifik: 200.23.18.0/23. Berdasarkan prinsip Longest Prefix Match, router di seluruh Internet yang melihat rute agregat /20 dan rute spesifik /23 akan memilih rute /23, sehingga paket untuk Organisasi 1 berhasil dialihkan ke ISP baru tanpa merusak rute agregat ISP lama.

Peran ICANN

ICANN (Internet Corporation for Assigned Names and Numbers) mengelola zona root DNS, menetapkan nama domain TLD, dan mengalokasikan blok alamat IPv4/IPv6 ke 5 Regional Internet Registries (RRs) di dunia (ARIN, RIPE NCC, APNIC, LACNIC, AFRINIC).

W07.4 — NAT (Network Address Translation)

Solusi memperpanjang usia IPv4 dengan berbagi satu alamat publik untuk seluruh jaringan lokal.

Motivasi dan Cara Kerja NAT

Seluruh perangkat di dalam jaringan lokal (misal jaringan rumah 10.0.0.0/24) memiliki alamat IP privat (10.0.0.1, 10.0.0.2). Dari sudut pandang Internet luar, seluruh jaringan tersebut hanya terlihat memiliki satu alamat IP publik tunggal (misal 138.76.29.7).

Mekanisme NAT Translation Table:

  1. Paket Keluar: Host lokal 10.0.0.1:3345 mengirim paket ke web server 128.119.40.186:80. Router NAT mengganti Source IP dan Source Port menjadi alamat publik dan nomor port baru: 138.76.29.7:5001. Router mencatat pasangan ini ke dalam NAT Table.
  2. Paket Masuk: Web server membalas ke 138.76.29.7:5001. Router NAT memeriksa tabel, menemukan bahwa port 5001 adalah milik 10.0.0.1:3345, mengganti Destination IP/port, lalu meneruskan paket ke host lokal.

Translasi Alamat NAT: Memetakan banyak host privat ke satu IP publik WAN menggunakan tabel port 16-bit.

W07.5 — Generalized forwarding dan OpenFlow

Evolusi dari destination-based forwarding menjadi aturan match-plus-action lintas layer.

Konsep Match-plus-Action

Pada router tradisional, pencocokan hanya didasarkan pada alamat IP tujuan (destination-based). Pada Generalized Forwarding, router memeriksa berbagai bit field pada header paket dari layer 2, 3, dan 4 secara fleksibel, lalu menjalankan aksi yang ditentukan:

Struktur Entri Flow Table:

[ Match | Action | Stats ]

  • Match: pola nilai header yang dicocokkan (mendukung wildcard *).
  • Action: forward(port), drop, modify-field, atau send-to-controller.
  • Stats: penghitung jumlah paket (packet counter) dan byte yang cocok.

12 Field Header OpenFlow

OpenFlow dapat mencocokkan field dari tiga layer sekaligus:

  • Link Layer: Ingress Port, Source MAC, Destination MAC, Ethernet Type, VLAN ID, VLAN Priority.
  • Network Layer: Source IP, Destination IP, IP Protocol, IP ToS (Type of Service).
  • Transport Layer: TCP/UDP Source Port, TCP/UDP Destination Port.

W07.6 — Middleboxes dan arsitektur Internet

Perangkat perantara jaringan di luar fungsi router standar.

Definisi Middlebox (RFC 3234)

Middlebox: setiap kotak perantara yang menjalankan fungsi di luar fungsi standar router IP di sepanjang jalur data antara host sumber dan host tujuan. Contoh: NAT router, Firewall, Intrusion Detection System (IDS), Load Balancer, Web Cache/Proxy, dan CDN node.

Model Jam Pasir Internet (IP Hourglass)

Internet dirancang dengan arsitektur "Jam Pasir":

  • Thin Waist (Pinggang Sempit) = IP: satu-satunya protokol network layer yang wajib diimplementasikan oleh miliaran perangkat di dunia agar semua orang bisa saling terhubung.
  • Di atas IP terdapat beragam protokol transport (TCP, UDP, QUIC) dan ribuan aplikasi (HTTP, DNS, streaming).
  • Di bawah IP terdapat beragam teknologi link dan fisik (Ethernet, WiFi, seluler 4G/5G, fiber optic, satelit).
  • Kemunculan middlebox diibaratkan "love handles" di pinggang sempit model jam pasir Internet modern.

Model Jam Pasir Internet: Protokol IP bertindak sebagai pinggang sempit (thin waist) pemersatu seluruh teknologi.

End-to-End Argument (Saltzer, Reed, Clark 1981)

Prinsip arsitektur dasar Internet: fungsionalitas komunikasi (seperti keandalan transfer data dan enkripsi) hanya dapat diimplementasikan secara lengkap dan benar di end point (edge) jaringan dengan bantuan aplikasi. Menyediakan fungsi tersebut di dalam core jaringan tidak lengkap dan membebani router. Oleh karena itu, network core harus tetap sederhana, sedangkan kecerdasan diletakkan di edge.

W07.7 — Topik tambahan: fragmentasi IP dan DHCP Wireshark

Penanganan paket melebihi batas MTU link fisik pada IPv4.

Fragmentasi Datagram IPv4

Setiap link layer memiliki MTU (Maximum Transfer Unit), yaitu ukuran frame maksimum yang dapat dibawanya (misal Ethernet MTU = 1500 byte). Jika ukuran datagram IP lebih besar dari MTU link berikutnya, router IPv4 akan memecah datagram menjadi beberapa fragmen.

  • Identification (16 bit): nomor ID yang sama disematkan pada seluruh fragmen dari datagram asli yang sama.
  • Fragflag (More Fragments flag): bernilai 1 jika masih ada fragmen berikutnya; bernilai 0 pada fragmen terakhir.
  • Fragment Offset (13 bit): posisi data fragmen dalam satuan blok 8 byte (Offset = byte offset / 8).
  • Reassembly: perakitan ulang fragmen menjadi datagram utuh hanya dilakukan di host tujuan akhir, bukan di router perantara.

W08.1 — Pengantar control plane dan abstraksi graf

Bagaimana tabel forwarding (data plane) dihitung oleh kecerdasan control plane.

Dua Fungsi Network Layer (Review)

  • Forwarding (Data Plane): aksi lokal router memindahkan paket dari port input ke port output berdasarkan forwarding table (nanodetik, hardware).
  • Routing (Control Plane): menentukan rute ujung-ke-ujung (end-to-end path) yang dilalui paket dari host sumber ke host tujuan (milidetik, software).

Dua Pendekatan Mengorganisasi Control Plane

  1. Per-Router Control (Tradisional): algoritma routing individual berjalan di setiap router dan saling berinteraksi mengirim pesan link-state atau distance-vector untuk membangun forwarding table masing-masing.
  2. Logically Centralized Control (SDN): software controller jarak jauh yang terpusat secara logis menghitung forwarding table secara global dan memasangnya langsung ke perangkat switch. Router dilengkapi Control Agent (CA) untuk menerima instruksi controller.

Abstraksi Graf Jaringan

Jaringan dimodelkan sebagai graf terhubung $G = (N, E)$:

  • $N$: himpunan router (nodes) $= \{u, v, w, x, y, z\}$.
  • $E$: himpunan link langsung (edges) yang menghubungkan pasangan router.
  • $c(a,b)$: biaya (cost) dari link langsung antara node $a$ dan $b$. Jika tidak terhubung langsung, $c(a,b) = \infty$.
  • Biaya link dikonfigurasi oleh network operator: bisa selalu bernilai 1 (hop count), berbanding terbalik dengan bandwidth (link cepat bercost rendah), atau berbanding lurus dengan kongesti.

W08.2 — Link-State routing: algoritma Dijkstra

Menghitung least-cost path dari satu node sumber ke seluruh node lain di jaringan.

Notasi Algoritma Dijkstra

  • $c(x,y)$: cost link langsung dari $x$ ke $y$ (bernilai $\infty$ jika bukan tetangga langsung).
  • $D(v)$: estimasi biaya rute terpendek saat ini dari sumber ke node tujuan $v$.
  • $p(v)$: predecessor node (node tetangga pendahulu sebelum $v$ di sepanjang jalur rute).
  • $N'$: himpunan node yang rute terpendeknya sudah definitif diketahui.

Langkah Algoritma Dijkstra

  1. Inisialisasi: Masukkan node sumber $u$ ke $N'$ ($N' = \{u\}$). Untuk semua node $v$, set $D(v) = c(u,v)$ jika bertetangga dengan $u$, atau $D(v) = \infty$ jika tidak.
  2. Loop:
    • Cari node $w$ di luar $N'$ yang memiliki nilai $D(w)$ paling minimum.
    • Tambahkan $w$ ke dalam himpunan $N'$.
    • Perbarui nilai $D(v)$ untuk setiap tetangga $v$ dari $w$ yang belum ada di $N'$:
      D(v) = min( D(v), D(w) + c(w,v) )
  3. Ulangi langkah Loop hingga seluruh node berada di dalam $N'$.

Contoh Hitungan Dijkstra (Sumber = Node u)

Topologi: u–v=2, u–x=1, u–w=5, v–x=2, v–w=3, x–w=3, x–y=1, w–y=1, w–z=5, y–z=2.

Hasil Forwarding Table di Node u:

Dengan menelusuri rantai predecessor dari node tujuan ke sumber:

  • Tujuan $v$: rute langsung keluar lewat interface (u, v).
  • Tujuan $x$: rute langsung keluar lewat interface (u, x).
  • Tujuan $y$: lewat jalur $u \rightarrow x \rightarrow y$, keluar lewat interface (u, x).
  • Tujuan $w$: lewat jalur $u \rightarrow x \rightarrow y \rightarrow w$, keluar lewat interface (u, x).
  • Tujuan $z$: lewat jalur $u \rightarrow x \rightarrow y \rightarrow z$, keluar lewat interface (u, x).

Kompleksitas dan Masalah Osilasi pada Link-State

  • Kompleksitas Komputasi: untuk $n$ node, iterasi membutuhkan $\frac{n(n+1)}{2}$ komparasi $\rightarrow \mathbf{O(n^2)}$ (dapat dioptimalkan menjadi $O(n \log n)$ dengan data structure heap).
  • Message Complexity: paket broadcast link-state melintasi link jaringan dengan kompleksitas $\mathbf{O(n^2)}$.
  • Route Oscillations: jika biaya link dihitung berdasarkan volume trafik (kongesti), rute dapat berayun bolak-balik terus-menerus. Trafik dialihkan ke jalur sepi $\rightarrow$ jalur tersebut menjadi macet dan biayanya melonjak $\rightarrow$ algoritma mengalihkan kembali ke jalur awal $\rightarrow$ siklus berulang tanpa henti. Solusinya: jangan jadikan metrik link murni berbasis beban sesaat.

W08.3 — Distance Vector routing: algoritma Bellman-Ford

Algoritma rute terdistribusi berbasis pemrograman dinamis (dynamic programming).

Persamaan Bellman-Ford

Misalkan $D_x(y)$ adalah estimasi biaya rute terpendek dari node $x$ ke tujuan $y$:

D_x(y) = min_v { c(x,v) + D_v(y) }

Nilai minimum diambil atas seluruh tetangga langsung $v$ dari $x$. Node tetangga $v$ yang menghasilkan nilai minimum adalah next-hop router menuju tujuan $y$.

Contoh Perhitungan: Node $u$ bertetangga dengan $v, x, w$. Diketahui biaya link $c(u,v)=2, c(u,x)=1, c(u,w)=5$. Estimasi jarak dari masing-masing tetangga ke tujuan $z$ adalah $D_v(z)=5, D_x(z)=3, D_w(z)=3$.

D_u(z) = min{ 2 + D_v(z), 1 + D_x(z), 5 + D_w(z) }
       = min{ 2 + 5, 1 + 3, 5 + 3 } = min{ 7, 4, 8 } = 4

Karena nilai minimum dicapai lewat tetangga $x$, maka next-hop untuk tujuan z adalah x.

Sifat Algoritma Distance Vector

  • Iterative & Asynchronous: komputasi lokal diulang setiap kali terjadi perubahan biaya link lokal atau saat menerima pesan update vektor jarak dari tetangga.
  • Distributed & Self-Stopping: setiap node hanya mengirim pesan update ke tetangga jika dan hanya jika estimasi vektor jaraknya berubah. Jika tidak ada perubahan, tidak ada pesan yang dikirim (algoritma berhenti sendiri).

Penyebaran Informasi (Diffusion)

Informasi status jaringan menyebar bertahap per hop: pada $t=0$ hanya diketahui node asal; pada $t=1$ menyebar ke tetangga 1-hop; pada $t=2$ menyebar 2-hop; hingga akhirnya konvergen ke seluruh jaringan.

Good News Travels Fast vs Bad News Travels Slow

  • Good News Travels Fast: jika biaya link turun (misal dari 4 menjadi 1), informasi rute yang lebih murah menyebar sangat cepat dan konvergen hanya dalam 2–3 iterasi.
  • Bad News Travels Slow (Count-to-Infinity Problem): jika biaya link naik drastis (misal link $x$–$y$ putus atau naik dari 4 menjadi 60), node $y$ mengira masih bisa mencapai $x$ lewat tetangganya $z$ dengan biaya murah (karena $z$ sebelumnya mengabarkan rute lewat $y$). Keduanya saling mengupdate secara melingkar (routing loop), menaikkan estimasi biaya satu per satu ($6, 7, 8, \dots$) hingga mencapai nilai $\infty$.

W08.5 — Routing hierarki dan protokol intra-AS (OSPF)

Bagaimana skala miliaran host dan otonomi ISP dikelola di Internet.

Mengapa Perlu Routing Hierarki?

  • Skala (Scale): miliaran host tujuan di dunia tidak mungkin ditampung dalam satu tabel routing tunggal yang datar (flat); pertukaran rute akan menenggelamkan bandwidth link.
  • Otonomi Administratif: Internet adalah network of networks. Setiap pengelola ISP berhak mengatur kebijakan routing internal di jaringannya sendiri tanpa campur tangan pihak luar.

Konsep Autonomous System (AS)

Router dikelompokkan ke dalam domain administratif bernama Autonomous System (AS):

  • Intra-AS Routing (Interior Gateway Protocol / IGP): routing antar router di dalam satu AS yang sama. Seluruh router di AS tersebut menjalankan protokol IGP yang sama.
  • Inter-AS Routing (Exterior Gateway Protocol / EGP): routing antar AS yang berbeda. Router perbatasan di tepi AS disebut Gateway Router.

Tiga Protokol Intra-AS (IGP) Terkenal

ProtokolBasis AlgoritmaKarakteristik

Fitur-Fitur Kunci OSPF

  • Keamanan: seluruh pesan OSPF diautentikasi (mencegah router palsu menyusup).
  • Multi-metrik: mendukung kalkulasi biaya berbasis bandwidth, delay, atau reliabilitas.
  • Hierarchical OSPF: pada AS skala besar, jaringan dibagi menjadi Area 0 (Backbone Area) dan Local Areas.
    • Internal Routers: menjalankan flooding LSA terbatas hanya di dalam areanya sendiri.
    • Area Border Routers (ABR): merangkum rute di areanya dan mengiklankannya ke area backbone.
    • AS Boundary Routers (ASBR): router gateway yang terhubung ke AS luar.

Hierarchical OSPF: Area 0 menghubungkan area lokal melalui Area Border Router (ABR) dan AS Boundary Router (ASBR).

W08.6 — Routing antar-AS: BGP (Border Gateway Protocol)

BGP (RFC 4271) adalah protokol inter-domain de facto yang menyatukan seluruh Internet ("the glue of the Internet").

Peran BGP

BGP adalah protokol Path Vector yang bertugas mengumumkan ketersediaan subnet (reachability) dan jalur rute ke seluruh dunia: "Saya berada di sini, ini daftar tujuan yang bisa saya jangkau, dan ini jalur AS yang harus dilewati."

  • eBGP (External BGP): sesi pertukaran rute antar router gateway di dua AS yang berbeda.
  • iBGP (Internal BGP): sesi penyebaran informasi rute eksternal ke seluruh router internal di dalam satu AS.
  • Sesi BGP berjalan di atas koneksi TCP semi-permanen pada port 179.

Perambatan Rute BGP: eBGP bertukar rute antar-AS; iBGP mendistribusikan rute eksternal ke seluruh router internal.

Atribut Jalur BGP (Path Attributes)

Rute yang diiklankan BGP terdiri dari Prefix Tujuan + Atribut:

  • AS-PATH: deretan nomor AS yang telah dilintasi oleh pengumuman rute (misal: AS 67, AS 17, AS 223). Berfungsi penting untuk mendeteksi dan mencegah looping (jika nomor AS sendiri ada di daftar, iklan rute ditolak).
  • NEXT-HOP: alamat IP interface router spesifik yang menjadi pintu gerbang menuju AS berikutnya.

Policy-Based Routing & Hot Potato Routing

  • Policy-Based Routing: keputusan memilih atau mengiklankan rute didorong oleh kebijakan ekonomi/bisnis, bukan sekadar jarak fisik. ISP komersial tidak mau menjadi perantara transit gratis bagi trafik kompetitor kecuali jika berasal dari atau menuju pelanggan berbayar (customer).
  • Hot Potato Routing: router memilih gateway perbatasan lokal yang memiliki biaya intra-domain (OSPF) terkecil untuk melempar paket keluar dari AS-nya secepat mungkin ("seperti memegang kentang panas"), tanpa mempedulikan berapa banyak lompatan AS di luar sana.

Urutan Seleksi Rute BGP (Route Selection Rules):

  1. Pilih rute dengan nilai Local Preference tertinggi (kebijakan administratif lokal).
  2. Jika sama, pilih rute dengan AS-PATH terpendek.
  3. Jika sama, pilih gateway dengan NEXT-HOP terdekat (Hot Potato Routing).
  4. Jika masih sama, gunakan kriteria penentu tambahan (BGP identifier).

W08.7 — SDN Control Plane

Pemisahan control plane dan data plane secara horizontal menuju era jaringan terprogram.

Analogi Evolusi SDN: Mainframe Menuju PC

EraMainframe (Router Tradisional)Era PC Terbuka (SDN)
ArsitekturVertically Integrated: hardware, OS, dan aplikasi menyatu dalam satu kotak proprietary dari vendor tunggal (misal Cisco IOS). Inovasi lambat.Horizontal & Open: hardware commodity standar, Network OS terpisah, aplikasi kontrol independen berbasis open API.

Tiga Lapisan Arsitektur SDN

  1. Data-Plane Switches: perangkat sakelar cepat berbasis hardware commodity yang menjalankan generalized forwarding berbasis Flow Table (OpenFlow).
  2. SDN Controller (Network OS): memelihara basis data status topologi jaringan terdistribusi secara global. Menyediakan Northbound API (RESTful) untuk aplikasi di atasnya, dan Southbound API (OpenFlow) untuk switch di bawahnya.
  3. Network-Control Applications: program logika cerdas ("otak") yang mengimplementasikan routing (Dijkstra), load balancing, firewall, atau traffic engineering. Aplikasi ini terpisah dari controller dan dapat dibuat oleh developer pihak ketiga.

Arsitektur Tiga Lapisan SDN: Pemisahan tegas aplikasi cerdas (Northbound), Controller Network OS, dan hardware switch (Southbound OpenFlow).

Protokol OpenFlow (Southbound Protocol)

Beroperasi antara controller dan switch melalui koneksi TCP (opsional TLS):

  • Controller-to-Switch:
    • features: menanyakan kapabilitas switch.
    • configure: membaca atau menyetel parameter switch.
    • modify-state: menambah, menghapus, atau mengubah entri di Flow Table OpenFlow.
    • packet-out: menyuruh switch mengirimkan paket tertentu keluar dari port tertentu.
  • Switch-to-Controller:
    • packet-in: mengirim paket yang tidak cocok dengan aturan flow table ke controller untuk dianalisis.
    • flow-removed: mengabarkan bahwa suatu aturan flow table telah kedaluwarsa.
    • port-status: mengabarkan perubahan status link (misal port mati/down).

Contoh controller nyata: ONOS (open-source carrier grade) dan Google ORION (arsitektur SDN untuk data center Jupiter dan jaringan WAN privat B4 milik Google).

W08.8 — ICMP dan Traceroute

Protokol pelaporan status jaringan dan diagnosis jalur.

Fungsi ICMP (Internet Control Message Protocol)

ICMP berjalan di Network Layer di atas IP (dibawa sebagai payload datagram IP). Fungsinya mengomunikasikan informasi kontrol dan pelaporan error antar host dan router.

Format Pesan ICMP: terdiri dari field Type (8 bit), Code (8 bit), Checksum, serta 8 byte pertama dari datagram IP penyebab error (agar pengirim tahu paket mana yang bermasalah).

TypeCodeDeskripsiKegunaan
00Echo ReplyBalasan ping.
80Echo RequestPermintaan uji koneksi (ping).
30 / 1Dest. Network / Host UnreachableRute ke jaringan atau host tujuan tidak ditemukan.
33Dest. Port UnreachableTidak ada proses aplikasi yang mendengarkan di port tersebut.
110TTL Expired in TransitPaket dibuang karena hop limit/TTL habis (fondasi Traceroute).

Cara Kerja Traceroute Menggunakan ICMP

  1. Pengirim mengirim serangkaian paket UDP dengan nomor port tujuan acak yang tidak digunakan.
  2. Set pertama dikirim dengan TTL = 1 (3 probe). Router hop pertama mengurangi TTL menjadi 0, membuang paket, lalu membalas pengirim dengan pesan ICMP Type 11 Code 0 (TTL Expired). Pengirim mencatat IP router hop 1 dan menghitung RTT.
  3. Pengirim mengulang dengan TTL = 2 untuk mengungkap hop kedua, lalu TTL = 3, dan seterusnya.
  4. Kondisi Berhenti: Ketika paket akhirnya tiba di host tujuan akhir, host tujuan melihat bahwa port UDP tersebut tidak aktif, lalu mengembalikan pesan ICMP Type 3 Code 3 (Port Unreachable). Saat menerima pesan ini, pengirim menghentikan penelusuran.

Prinsip Kerja Traceroute: Memanfaatkan pesan ICMP TTL Expired (Type 11) dan Port Unreachable (Type 3 Code 3) untuk memetakan tiap hop.

W08.9 — Network management: SNMP, NETCONF, dan YANG

Monitoring, pemeliharaan, dan konfigurasi ribuan perangkat jaringan terkoordinasi.

Tiga Pendekatan Pengelolaan Jaringan

  1. CLI (Command Line Interface): administrator mengetik perintah langsung per perangkat melalui sesi secure shell (SSH). Rentan kesalahan manusia (human error).
  2. SNMP / MIB: pendekatan berbasis polling untuk membaca dan mengubah data status operasional perangkat.
  3. NETCONF / YANG: pendekatan modern berbasis remote procedure call (RPC) deklaratif untuk mengonfigurasi banyak perangkat secara holistik dan konsisten.

SNMP (Simple Network Management Protocol)

  • Request / Response Mode: managing server mengirimkan pesan GetRequest, GetNextRequest, atau SetRequest ke agent di perangkat; agent membalas dengan Response.
  • Trap Mode: agent di perangkat secara mandiri mengirimkan pesan Trap ke server manajer untuk melaporkan kejadian luar biasa mendesak (misal link down atau suhu overheat).
  • MIB (Management Information Base): modul database variabel operasional perangkat (misal UDPInDatagrams, UDPNoPorts) yang didefinisikan menggunakan bahasa SMI.

NETCONF dan YANG

  • NETCONF: protokol konfigurasi jaringan berbasis XML melalui transport aman (TLS). Mendukung transaksi multi-perangkat dengan atomic commit (semua perangkat sukses menerapkan konfigurasi, atau dibatalkan bersama/rollback jika satu gagal). Operasi utama meliputi <get-config>, <edit-config>, <lock>, dan <unlock>.
  • YANG: bahasa pemodelan data (data modeling language) yang mendefinisikan struktur, sintaks, tipe data, dan aturan validitas konfigurasi NETCONF, menjamin konsistensi sintaks sebelum dikirim ke perangkat.

Ringkasan W08

  • Control plane menentukan rute end-to-end via per-router control (tradisional) atau SDN logically centralized control.
  • Algoritma Dijkstra (Link-State) memakai broadcast global untuk menghitung rute terpendek dengan kompleksitas $O(n^2)$. Rentan osilasi jika metrik bergantung trafik.
  • Algoritma Bellman-Ford (Distance Vector) menghitung rute dari pertukaran lokal antar tetangga. Mengalami fenomena good news travels fast dan bad news travels slow (count-to-infinity).
  • Routing Internet diorganisasi secara hierarkis dalam Autonomous System (AS). OSPF adalah protokol intra-AS berbasis Link-State dengan hierarki area.
  • BGP adalah protokol inter-AS berbasis Path Vector via sesi TCP. BGP memilih rute berdasarkan kebijakan (policy), panjang AS-PATH, dan hot-potato routing.
  • SDN memisahkan data plane dan control plane dengan protokol OpenFlow di southbound dan REST di northbound.
  • ICMP melaporkan error jaringan (TTL expired, destination unreachable) dan mendukung kerja Traceroute.
  • Manajemen jaringan berevolusi dari SNMP/MIB menuju NETCONF/YANG berbasis XML RPC over TLS dengan atomic commit.

Soal #1 [W01] • Hitungan Numerik

Ketika sebuah paket tiba di router, ada 1 paket yang baru setengahnya terkirim dan 4 paket lainnya sedang mengantri di buffer. Paket dikirimkan berdasarkan urutan antrian (FIFO). Anggap semua paket berukuran 1 KByte dan rate transmisi adalah 2 Mbps.
Hitung delay antrian (queuing delay) dari paket yang baru datang tersebut (dalam satuan detik atau second)!
Asumsi: 1 KByte = 1000 Byte, 1 Mbit = 10⁶ bit.

Lihat Kunci & Pembahasan

Kunci Jawaban Resmi: 0.018

Pembahasan: Total paket di depan paket yang baru datang adalah 0,5 (paket yang sedang diproses setengah jalan) + 4 (paket mengantri utuh) = 4,5 paket.
Total bit yang harus dituntaskan router = $4{,}5 \times 1000\text{ Byte} \times 8\text{ bit/Byte} = 36.000\text{ bit}$.
Rate link $R = 2\text{ Mbps} = 2.000.000\text{ bit/detik}$.
$$d_{queue} = \frac{\text{Total Bit}}{R} = \frac{36.000}{2.000.000} = \mathbf{0{,}018\text{ detik (18 ms)}}.$$

⚠️ Jebakan & Catatan Ujian: Jangan lupa mengalikan ukuran Byte ke bit (× 8)! Dan hitung paket yang baru setengah terkirim sebagai 0,5.

Soal #3 [W01] • Hitungan Numerik

Host A dan Host B dihubungkan oleh 2 link yang masing-masing berjarak 200 km dan 400 km. Kedua link ini dihubungkan oleh sebuah packet switch di mana delay processing pada packet switch adalah 1 msec dan transmission rate pada tiap link sebesar 1 Mbit/s. Asumsi tidak ada queueing delay dan kecepatan propagasi pada kedua link adalah $2 \times 10^8\text{ m/s}$. Berapakah end-to-end delay ketika Host A mengirim sebuah paket berukuran 2 KByte ke Host B (dalam satuan detik)?
Asumsi: 1 KByte = 1000 Byte, 1 Mbit = 1000 Kbit = 10⁶ bit.

Lihat Kunci & Pembahasan

Kunci Jawaban Resmi: 0.036

Pembahasan: Komponen delay end-to-end:
1. Transmission delay ($d_{trans}$): Paket harus ditransmisikan 2 kali (sekali oleh Host A, sekali oleh Switch).
$$d_{trans} = \frac{L}{R} = \frac{2000 \times 8}{1.000.000} = \frac{16.000}{1.000.000} = 0{,}016\text{ s per link}.$$Untuk 2 link: $2 \times 0{,}016 = \mathbf{0{,}032\text{ s}}$.
2. Propagation delay ($d_{prop}$):
• Link 1 (200 km): $\frac{200.000\text{ m}}{2 \times 10^8\text{ m/s}} = 0{,}001\text{ s} = 1\text{ ms}$.
• Link 2 (400 km): $\frac{400.000\text{ m}}{2 \times 10^8\text{ m/s}} = 0{,}002\text{ s} = 2\text{ ms}$.
Total $d_{prop} = 0{,}001 + 0{,}002 = \mathbf{0{,}003\text{ s}}$.
3. Processing delay ($d_{proc}$): $1\text{ ms} = \mathbf{0{,}001\text{ s}}$.
4. Total Delay End-to-End:
$$d_{end-end} = 2(d_{trans}) + d_{prop1} + d_{prop2} + d_{proc} = 0{,}032 + 0{,}003 + 0{,}001 = \mathbf{0{,}036\text{ detik}}.$$

⚠️ Jebakan & Catatan Ujian: Banyak yang lupa bahwa paket beroperasi secara store-and-forward, sehingga transmission delay $L/R$ terjadi di SETIAP hop link (2 kali).

1. Berapakah jumlah fragmen yang dihasilkan?
2. Berapakah ukuran fragmen pertama (dalam bytes)?
3. Berapakah ukuran fragmen terakhir (dalam bytes)?

Lihat Kunci & Pembahasan

Kunci Jawaban Resmi: Jumlah fragmen = 3; Fragmen pertama = 1500; Fragmen terakhir = 40

Pembahasan: • Datagram awal: Total 3000 B = 20 B Header IP + 2980 B Data Payload.
• Link MTU = 1500 B. Kapasitas data maksimum per fragmen = $1500 - 20 = 1480\text{ B}$ (harus kelipatan 8, dan 1480 habis dibagi 8: $1480 / 8 = 185$).
• Fragmen 1: 20 B Header + 1480 B Data = 1500 B (FragFlag = 1, Offset = 0).
• Fragmen 2: 20 B Header + 1480 B Data = 1500 B (FragFlag = 1, Offset = 185).

• Sisa data yang belum terkirim = $2980 - 2960 = \mathbf{20\text{ B}}$.
• Fragmen 3 (Terakhir): 20 B Header IP + 20 B Sisa Data = 40 B (FragFlag = 0, Offset = $2960 / 8 = 370$).

⚠️ Jebakan & Catatan Ujian: Ini adalah jebakan nomor 1 di kuis SCELE! Jawaban ukuran fragmen terakhir BUKAN 1500 B atau 20 B, melainkan 40 B (karena ukuran fragmen selalu menyertakan 20 byte header IP baru!).

Soal #7 [W04] • Analisis Grafik Congestion Control

Gambar di bawah mengilustrasikan evolusi dari TCP congestion window menggunakan TCP Reno. Sumbu x menyatakan transmission round dalam satuan RTT, sedangkan sumbu y menggambarkan ukuran cwnd dalam satuan MSS. Pada kondisi awal, cwnd = 1, dan ssthresh = 8.
Berapa THROUGHPUT rata-rata mulai RTT ke 12 sampai RTT 16 dalam satuan cwnd/RTT (catatan: segmen yang dikirim pada RTT ke 12 tidak ikut dihitung. Tulis jawaban dalam bentuk desimal)?

Lihat Kunci & Pembahasan

Kunci Jawaban Resmi: 5.5 (atau 5.75 tergantung rentang round)

• Segmen pada RTT 12 tidak dihitung sesuai catatan soal. Maka ronde yang dihitung adalah RTT 13, 14, 15, dan 16 (4 interval):
- RTT 13: cwnd = 4
- RTT 14: cwnd = 5
- RTT 15: cwnd = 6
- RTT 16: cwnd = 7

⚠️ Jebakan & Catatan Ujian: Perhatikan instruksi soal: 'segment yang dikirim pada RTT ke 12 tidak ikut dihitung'. Jadi hanya rata-ratakan 4 titik setelah loss.
